## 二、两种整体方案及比较

### 方案 A — 集中式：一个"所长顾问"skill，各步按需调用

把 `cao-thinking` 与 `yongjun-thinking` 两个人物 skill 作为唯一真源，流水线各步（立论、预读、必要时侦察）在需要时**调用 skill 生成提示**，各步提示词里不写死任何判据语句。

### 方案 B — 分布式：拆成模具语句，分嵌各步提示词

把两人的思维签名拆成一句句"模具"，直接写进侦察 / 立论 / 组材 / 预读各步的提示词段落里，不依赖 skill 调用。

### 方案 C — 混合（本稿推荐）：skill 为源，关键步以"调用生成"注入，轻量字段留模板

两 skill 为唯一真源；**立论步与预读步以 skill 调用注入**（产出的是"先问什么、怎么切"的生成式提示）；已定型的轻量点（用途类型、读者层级）留作**模板字段**；侦察分歧轴心法可作提示词段落但引用 skill 口径。

### 三角度比较

| 角度 | A 集中式 | B 分布式 | C 混合（推荐） |
|---|---|---|---|
| **维护成本** | 低：改一处 skill 全线生效 | 高：语句散落多步，改动要逐处同步、易漏 | 低—中：判断逻辑集中于 skill，仅少数模板字段单列 |
| **蒸馏产物更新路径**（论文蒸完后如何替换先验假设） | 好：skill 是单一真源，换 skill 内核＝全流水线更新，接入点不动 | 差：模具写死在各步，更新要逐处改且极易漏，先验假设与实证混在提示词里分不清 | 好：换 skill 内核即更新立论/预读；模板字段（三类型/读者层级）本就稳定、少动 |
| **防评分器化** | 中：skill 输出可控为生成式，但若被当"评判器"调用仍有风险 | **高危**：散落语句最易被后人顺手改成"检查有没有 X"的 checklist（盲测 v2 判死路线） | 高：skill 强制产出"先问什么"的生成式提示，天然难被改成清单；模板字段只承载点选项、不承载判据 |

### 推荐

**取方案 C（混合，偏集中）。** 理由：
1. 更新路径是这件事的命门——论文蒸馏是**后到**的（Phase A 还在等语料），先验假设日后必被证实/证伪并替换（行动方案 B2/B3）。只有"skill 为唯一真源"能让替换一步到位，分布式会把先验假设焊死在几十处提示词里。
2. 防评分器化上，分布式最危险：一句句判据语句躺在提示词里，后人最容易顺手改成"有没有鲜明观点/有没有挂纲要"。集中于 skill、且强制生成式产出，是对盲测 v2 教训最稳的工程护栏。
3. 与既定计划自洽：行动方案 Phase D 与重构 §六 已把接入点钉在**观点模具（立论步）＋预读提词（审查尾部）两处**，方案 C 正好是"这两处调 skill、其余留模板"，改动量最小。

## 四、需用户拍板的问题（≤5）

1. **整体方案选 A / B / C？** 倾向 **C（混合，偏集中）**。理由：论文蒸馏后必须能一步替换先验假设，只有 skill 单一真源做得到，且最防清单化。
2. **纲领文件锚定（曹6）证据最薄（仅场外证言＋间接转写、无逐字原话），先上还是等实证？** 倾向 **先以生成式追问在"预读提词"一处轻量试点、标低置信度**，等曹侧论文蒸出同款锚定行为再决定是否加重。理由：它是曹"三层兼备"战略层唯一可操作化的抓手，但重注入有过拟合场外证言的风险。
