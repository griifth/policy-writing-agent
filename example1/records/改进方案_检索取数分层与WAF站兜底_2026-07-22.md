# 改进方案：检索取数分层 ＋ WAF 硬站兜底（2026-07-22）

> 状态：**待实施**（本文只记方案，不改任何 skill/文档；实施前先看第五节验收）。
> 来源：2026-07-22 大陆 Windows 试跑前，就"全网检索是否需要 VPN、Playwright 能否补抓"做的三次真实测试。
> 一句话问题：**联邦级政府硬站（如 ed.gov）上了 Azure WAF+验证码，任何自动化实时抓取全被挡——这与 VPN 无关，是站点反自动化；工作流当前的"检索必须真联网、来源可点"隐含假设"能抓到全文"，对这类站不成立。**

---

## 一、实测证据（三法取 ed.gov，全败；对照 OECD 通）

| 方法 | 请求出口 | ed.gov（联邦硬站） | OECD（普通国际组织站） |
|---|---|---|---|
| WebSearch（搜索索引） | 美服务器 | ✅ 拿到标题+摘要+PDF 直链（索引存的） | ✅ |
| WebFetch（服务端抓取） | 美服务器 | ❌ HTTP 403 | ✅ |
| Playwright 抓 HTML 页 | 本地浏览器 | ❌ Azure WAF 验证码 | ✅ 整页完整渲染 |
| Playwright 抓 PDF 直链 | 本地浏览器 | ❌ 同样 Azure WAF 验证码（PDF 未绕过 WAF） | —— |

**两个被实测推翻的直觉（记录在案，防再犯）**：
1. "Playwright 是真浏览器能过反爬"——只对普通站成立；WAF+验证码站不成立。
2. "PDF 直链能绕过 HTML 的 WAF"——不成立，WAF 蹲在整站前面，PDF 一起拦。

**关键区分**：搜索引擎能"搜到"ed.gov 内容 = 它的索引早爬过、存了摘要；**≠ 能实时抓下全文**。发现层（知道有这份文件、拿到要点与直链）可行，全文层（把整份文件取下来）对硬站不可行。

## 二、根因

- 不是"墙"（大陆防火墙封的是特定服务，多数美 .gov 本可直连）；
- 不是"缺 VPN"（服务端出口在美国也照样 403）；
- 是**站点级反自动化**（Azure WAF + CAPTCHA），对全球所有自动化请求一视同仁，越是联邦级硬站越严。验证码按红线不得由 agent 破解。

## 三、改进方案（两部分）

### 3.1 检索 skill 增"取数分层兜底梯"（topic-material-search-v2）

把当前隐含的"真联网抓全文"细化为**三级取数梯，逐级降级、每级如实标注取数方式**：

1. **发现级**：WebSearch 拿标题+摘要+直链——用于态势速览与料包的"存在性/要点"层，标 `[SEARCH-SNIPPET]`；
2. **全文级·首选直抓**：WebFetch/Playwright 抓原始 URL——成功标 `[FULLTEXT-DIRECT]`；
3. **全文级·硬站兜底**（直抓遇 403/WAF/验证码时）：按序试 ①镜像源（archive.org 网页存档、ERIC、政府公报镜像）②权威二手源（智库/律所/学术转载，须能追到原文出处）③标 `[FULLTEXT-MIRROR]` 或 `[FULLTEXT-SECONDARY]` 并注原始出处；三条都不成 → 标 `[FULLTEXT-UNAVAILABLE·仅摘要]`，**绝不静默把摘要当全文、绝不编造正文**（守宪法零编造）。

- 落点：`skills/topic-material-search-v2/SKILL.md` 检索步骤＋`references/sourcing-standard.md` 增取数方式标签规范；
- 硬约束：料包每条材料除来源锚外，**增一个"取数方式"标签**，让撰写者一眼看出"这条是全文实取还是仅搜索摘要"——可信度分层可见（同"标注不处决"家法）。

### 3.2 依赖说明增联网准确注（替换乐观版）

`依赖说明.md` 联网那一行补注（准确版，非之前的乐观版）：

> 美国政府站分两类：**普通站（OECD 等）**Playwright 可补抓；**WAF/验证码站（ed.gov 等联邦硬站）**任何自动化方法都拿不到全文——发现靠 WebSearch 摘要，全文靠镜像源/二手源/真人下载。这与 VPN 无关，是站点反自动化。Google 系搜索若走本地执行路径（Playwright/浏览器自动化）在大陆需 VPN；走服务端 WebSearch 则不需要。

## 四、优先级与顺序

| # | 事项 | 优先级 | 依赖 |
|---|---|---|---|
| 1 | 3.2 文档注（低成本、防误解） | 高·可先行 | 无 |
| 2 | 3.1 取数分层标签（改检索 skill＋sourcing-standard） | 中·需一轮实测校准标签 | 找几个真实硬站/普通站样本回归 |
| 3 | 料包模板增"取数方式"列 | 中 | 随 3.1 |
| 4 | 大陆实机验证 Google 系搜索是否需 VPN（服务端 vs 本地路径） | 低·待用户 Windows 侧回测 | 用户在大陆机器测 |

## 五、实施前验收（防又一次直觉翻车）

- 3.1 的标签规范落地前，**先用 5–8 个真实源做回归**（含 2 个 WAF 硬站、2 个普通 .gov、2 个国际组织、1 个学术库），确认三级降级路径每条都跑得通、标签判定无歧义；
- 不得把"仅摘要"伪装成全文——这是本方案的核心红线，回归时专门抽验；
- 改动只动 topic-material-search-v2 与依赖说明，不碰宪法与其他 skill。

## 六、暂不做

- 不引入付费检索 API / 反验证码服务（违"零破解验证码"红线与自包含底色）；
- 不为单个硬站写死特例规则（做通用降级梯，不做站点黑白名单）。
