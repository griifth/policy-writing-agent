# 活性工作流：装配式方案（2026-07-12）

> 用户提出，Fable 5 细化。地位：设计记录。上承 `重构设计_方向书架构_2026-07-12.md`（触点/三闸/指标等决议全部继承），改变的是**执行形态**：不再造固化流水线，改为"图纸＋零件槽＋装配工"的装配式系统。

## 一句话

旧引擎是一条焊死的流水线；新系统每接一个任务，由调度智能体看图纸（元框架）现场装配一条只为本篇服务的流水线（实体化的模块提示词），用完即弃，全程留档。

## 四层结构

1. **图纸＝元框架**：从人稿语料库（~38 篇真实内参）提炼的功能槽位族谱——槽位定义一律为"替读者回答什么问题/服务什么决策动作"，含必选/可选/条件槽、排序与篇幅配比规律、形态变体、槽位依赖、判断密度承载点标注、分体裁变奏表。提炼提示词见 `712测试_派单提示词_2026-07-12.md` 追加节；产出落 `records/元框架提炼_2026-07-12/`。
2. **元模块＝四个抽象零件槽**：检索 / 构思 / 写作 / 审查。每个只定义契约（输入/产出/质量底线/注入点），不含具体提示词。审查元模块的内容已定死＝机械三闸＋预读提词（继承前决议，不回评分器路线）。
3. **实体化＝装配工现场造零件**：每篇按"元模块契约＋本篇结构单（从元框架按用途类型实例化）＋方向书＋按需调用 skill（yongjun-thinking→定题/立论；cao-thinking→构思/预读；v2 检索 skill→侦察与全量）"现场生成本篇专用模块提示词；全部实体落盘存档（沿用 generated_prompts 习惯）。
4. **调度智能体**：跑在"调度 SKILL"上的 agent（替代 runner.py）。调度 skill 写死**宪法**：三闸必跑、两触点（方向书/观点清单）必停、槽位不得自创评分、模块实体必须引用元框架槽位定义原文、全部实体落盘。宪法之外自由：增删槽位、重跑模块、中途补检索。Python 只留机械件（llm_client/三闸/导出/台账）。

## 与既定决议的继承关系

- 两触点、九十秒人力、方向书六栏、观点清单勾选——原样继承（712 沙箱已验证前半段）。
- 三闸＋预读提词、评分器禁令、落位方案 C（skill 单一真源、曹/永军分工路由）——原样继承。
- 验收指标：勾选率 / 采用句数 / 复购率 / 里程碑（所长真人盲评）——原样继承。
- 旧引擎（workflow/ 与 strategic_response_workflow/）冻结为兜底与 A/B 基线，零改动。

## 风险与焊点

| 风险 | 焊点 |
|---|---|
| "活"→不可复现 | 模块实体提示词全落盘＋台账；每 run 一个目录 |
| 调度 agent 漂移 | 宪法条款＋触点强制暂停＋首批 run 由总设计抽检实体质量 |
| 现场造提示词质量参差 | 实体必须引用元框架槽位定义原文；引不出即违宪 |
| 元框架被用成评分表 | 槽位定义句式铁律（"替读者回答什么问题"），提炼提示词内已焊死 |
| 元框架过拟合语料实态（含下限稿） | 提炼要求标注反例与"实态非规范"边界声明；判断密度承载点单独标注供构思模块加权 |
