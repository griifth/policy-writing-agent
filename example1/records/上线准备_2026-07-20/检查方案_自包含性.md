## 三、L1 扫描结果 · 一致性瑕疵（建议整改，均为小改）

1. **README 陈述过期**：README §一 仍写「v2 快照待 W2.6 刷新，刷新前包内快照仍为 v1 态」，但 `blueprints/元框架v2_问题主线.md` 已存在（快照头注 2026-07-16）。W2.6 实际已完成，README 该行应更新。
2. **report-clarify-v2 的沙箱残留在正文步骤里**：`skills/report-clarify-v2/SKILL.md` 第 94 行的执行步骤 1 仍以 `<ROOT>/712测试/testruns/…` 为主路径（括注才是真实用法 `runs/<run-id>/`）；`references/clarify_scope.md` 第 53、62 行同样以沙箱路径为主。新机上的全新 agent 有照字面执行、去找不存在目录的风险。建议主客对调：正文以 `runs/<run-id>/` 为主，沙箱说明降为历史注记。topic-material-search-v2 的 SKILL.md 头部沙箱注记同理。
3. **engine 文档写死 `example1` 目录名**：`engine/README.md`、`run_entity.py`、`deepseek_client.py` 的注释多处说「.env 在 example1/」。代码用的是相对定位（上一级目录），搬到任何位置都对；建议措辞统一为「direction_workflow/ 的上一级目录」，避免新机使用者按名找目录。
4. **本机安装件与包内副本路径策略不一致（双源风险）**：`~/.claude/skills/policy-report-assembler/SKILL.md` 的三张图纸指向 `records/` 真源绝对路径（问题反馈录 #02 的既定裁决），而包内副本指向 `blueprints/` 快照相对路径。同一 skill 两个实例读的是**不同的图纸文件**——真源与快照一旦不同步，两处跑出的行为会分叉。整包迁移后新机只有快照，无此问题；但在原机须记住这层差异。建议在 移植说明.md「skill 双份」条下补一句明示。
5. **包根两个未入库的 HTML**（`flow_visualization.html`、`multi_agent_flow.html`）：非运行件。要么入库定位为文档，要么移出包外，避免「包内文件皆运行所需」的预期被稀释。
6. **runs/ 与 _skill_snapshots/ 里的旧绝对路径**：历史留痕，移植说明已声明「勿修复」——检查时应排除，不算问题。

## 五、L2–L4 验证步骤（整改后执行）

```bash
# L2-1 机械闸自检（应只依赖包内两词表）
cd <新位置>/direction_workflow
python3 gates/precheck.py runs/2026-07-13-拔尖创新人才/outputs/成稿.md

# L2-2 排版脚本（先 pip install -r requirements.txt）
python3 tools/neican_docx.py runs/2026-07-13-拔尖创新人才/outputs/成稿.md /tmp/试排.docx

# L2-3 引擎干跑（无 .env 时应报「缺密钥」的明确错误而非路径崩溃）
python3 engine/run_entity.py --help
```

- **L3 搬迁演练**：`cp -R direction_workflow /tmp/迁移测试/` → 全新 agent 会话，只给一句「工作根＝/tmp/迁移测试/direction_workflow，读 skills/policy-report-assembler/SKILL.md，接单：<任一主题>，试跑单、agent 直写」→ 验收：14 步走通、两触点真停、四闸真跑、runs/<id>/ 形制齐、全程零次读包外文件（可由 agent 自报读过的路径清单核对）。
- **L4 生产链路**：在 /tmp/迁移测试/ 下（即包的上一级）放 `.env`，重跑一单，验证立论/组稿走 DeepSeek。

## 六、验收标准（「可迁移」的定义）

整包复制到任意新目录后：**不改包内任何文件**，仅需 ①包外放一个 .env（生产单才需要）②`pip install -r requirements.txt` ③可联网的 agent 会话——即可从「接单」跑到「初稿_可交付.docx」。全量模式 DS 复审与 runner hand-off 两项按移植说明声明为不可用，不计入失败。
