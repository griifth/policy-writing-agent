# run-review 成稿回顾可视化 skill 方案（2026-07-20）

> 需求（用户原话）：使用者想看成稿背后的相关资料包或其他资料时，以 skill 形式触发，自动生成一个展示的前端页面，帮助其可视化地回顾。
> 定位对接：这是"6-7 成论"的配套工程——机器的取舍必须可见、可捞回（定位拍板边界条款），回顾页就是撰写者行使终审权的仪表盘。

---

## 一、定位与使用场景

**一句话**：对任意一个 `runs/<id>/`，一键生成一张**自包含的单文件 HTML 回顾页**，把"这篇成稿是怎么来的"完整摊开——从方向书到料包到观点勾选到闸门到成稿，链路可点、来源可溯、被扔掉的可见。

典型场景：
1. **报送前终审**：撰写者拿着可交付稿，想核"这个数字哪来的、这条观点当时勾没勾、机器扔了什么料"——现在要在 runs/ 目录里翻十几个 md，回顾页一屏解决。
2. **向领导/同事展示**：解释"这份报告不是 AI 硬写的"时，回顾页本身就是流程证明（两触点留痕、四闸违例清单、来源锚全链）。
3. **复盘迭代**：跑完一单看哪段料被大量弃用、哪些观点被叉，为下一单校准。

## 二、触发与接口

- **skill 名**：`run-review`（中文显示名：成稿回顾）。落位 `direction_workflow/skills/run-review/`，与其他 skill 同规——可装 `~/.claude/skills/` 按名触发，也可按包内路径读取执行。
- **触发语**：「回顾这单」「回顾 <run-id>」「看看这篇成稿背后的资料」「生成回顾页」；给一个成稿文件路径也应能反查其所属 run。
- **输入**：`runs/<id>/` 目录（宪法§三标准形制）。缺件不报错——有什么展示什么，缺件位置显示"本单无此件"（旧单/试跑单形制不全属正常）。
- **输出**：`runs/<id>/outputs/回顾页.html`，**单文件、零外链**（CSS/JS/数据全内联，双击即开，可直接发微信/邮件给别人看，不依赖任何环境）。

## 三、页面信息架构（六区一链）

```
┌────────────────────────────────────────────────────┐
│ ① 单头卡：标题｜判型（六型之一＋一句话主线）｜日期  │
│    方向书四栏卡（议题/箭头/读者层级/禁区）｜台账数字 │
├────────────────────────────────────────────────────┤
│ ② 主线链视图（页面主体·核心交互）                   │
│    表现段 → 归因段 → 建议段（铁三角横向泳道）        │
│    每段下挂节 → 节下挂已勾观点句 → 观点挂证据锚      │
│    【点成稿小标题 ⇄ 高亮对应观点 ⇄ 高亮其料包来源】  │
├──────────────────────┬─────────────────────────────┤
│ ③ 观点清单区          │ ④ 料包区                     │
│   勾/叉/改 全量展示    │   按主线段分组的材料卡        │
│   叉掉的置灰不隐藏     │   来源·T级·（A3落地后）品味三问标注│
│   改过的显示 diff      │   边角料箱：弃用料＋弃用理由   │
├──────────────────────┴─────────────────────────────┤
│ ⑤ 闸门区：四闸＋主线保真违例清单（只列条目，零分数） │
│    precheck 读数表原样呈现                           │
├────────────────────────────────────────────────────┤
│ ⑥ 预读提词区：两顾问考题＋三翻模拟｜需作者定夺清单   │
└────────────────────────────────────────────────────┘
```

设计要点：
- **②主线链是灵魂**：其他区都是清单的换皮，唯有"成稿段落 ⇄ 观点 ⇄ 料"三级联动是 md 文件堆里做不到的——回答"这句话背后是哪条观点、那条观点背后是哪份料"只需两次点击。数据来源：论证结构单（节-观点映射）＋观点清单（观点-主线地址）＋料包/来源锚（观点-证据）。
- **③叉掉的观点、④边角料必须展示**（置灰/折叠但不隐藏）——这正是"可见、可捞回"家法在前端的兑现，也是本页区别于"美化版成稿"的根本。
- **⑤⑥数据原样搬运**，不加工不概括。

## 四、家法合规（红线，写进 SKILL.md）

1. **零分数零档位**：页面任何位置不出现评分、星级、百分比健康度之类；闸门区只列违例条目。（宪法第 3 条）
2. **零编造**：页面所有文字必须抽取自 run 内文件原文，生成器不新写任何结论性语句；抽不到的字段留空标"本单无此件"。（宪法第 7 条）
3. **可见可捞回**：叉掉的观点、边角料、反证、存疑标注必须呈现，默认折叠可以、删除不行。（6-7 成论）
4. **只读**：skill 对 run 目录只读，回顾页是新增产物，不改写任何既有落盘件。
5. **脱敏一致性**：页面模板不含真名；抽取自旧 run 的历史内容如含旧名/真名（历史留痕），原样展示但页脚注明"历史单产物，称谓为当时实况"。

## 五、技术形态与生成流程

- **形态**：纯静态单文件 HTML＋内联 vanilla JS/CSS，数据以内联 JSON 嵌入。不依赖 CDN、不依赖 python、不依赖服务器——与包的"自包含"原则一致。
- **生成方式（agent 执行，非脚本）**：skill 指挥执行 agent ①读 run 目录清点在场文件 → ②按抽取规约把各 md 解析成 JSON（观点行的勾/叉/改、料条目的来源锚、违例条目等，格式都来自七模板，结构稳定可解析）→ ③把 JSON 灌进 skill 自带的 HTML 模板（`references/page_template.html`）→ ④落盘并自检（打开无报错、六区齐、红线四条逐条过）。
- **为什么不写成 python 脚本**：run 内 md 是模板化但非严格结构化的（人改过、版本有别），agent 解析的容错远好于正则；且各单形制差异（旧单缺论证结构单等）需要判断力兜底。**代价**：生成结果有 6-7 成稳定性，页面底部放"数据抽取备注"栏，agent 自报哪些字段是推断的——同样标注不处决。
- **skill 目录结构**：
  ```
  skills/run-review/
  ├─ SKILL.md            触发/输入输出/生成流程/红线四条/自检清单
  └─ references/
     ├─ page_template.html   页面模板（六区骨架＋联动JS，占位符待灌数据）
     └─ 抽取规约.md           各文件→JSON 的字段映射表（对着七模板写）
  ```

## 六、实施排期（并入 7-21 方案为 W4.7）

| 步骤 | 内容 | 耗时 |
|---|---|---|
| 1 | 写 page_template.html＋抽取规约（对着七模板与宪法§三形制） | 半天 |
| 2 | 写 SKILL.md（含红线与自检） | 1 小时 |
| 3 | **试点**：对 `runs/2026-07-13-科技教研员`（件最全的单）生成首张回顾页，人工核六区与三级联动 | 1 小时 |
| 4 | 修模板 → 再对一个形制不全的旧单跑一次（验缺件容错） | 1 小时 |
| 5 | 入包（skills/run-review/）＋README/USAGE 各加一行＋移植说明 skill 清单更新 | 半小时 |

- 优先级建议：排在 W4.1 之后、与 W4.2 同档（都是"给人看的回应物"）；如果本周要给张老师演示，回顾页对"展示这套系统不是黑箱"的说服力可能比结构变体更大——**它把两触点、四闸、全溯源这些卖点变成了肉眼可见的东西**。
- 远期（不入本轮）：A3 料品味三问标注落地后，料卡自动带三问暂答；台账攒多后可做跨单总览页（多单对比），另立工单。
