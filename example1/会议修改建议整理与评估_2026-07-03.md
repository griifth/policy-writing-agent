## 一、背景与整体判断

- 会议以**盲测**方式让 5 位评审对 5 篇样本（3 篇 AI 写、2 篇人写）打分（1=能直接用 / 2=可供参考 / 3=不能用）。结论是 **AI 稿未明显胜出**——这是所有优化诉求的出发点。
- 主创当日**明确交办两大任务**：① **审核标准显化**（对应 S11）；② **角色定位**（对应 S2）。会议过程中又浮现出更高优先级的 **S1「探索性追问」**（主创称"这其实是最关键的问题、之前没想到"）。
- **时间线承诺**：下周五/六（约 7/11–12）完善功能 → 下下周一（约 7/13）展示 → 争取**7 月底前跑通试合**。
- **可申专利的三个卖点**（会议点名，需写进招商/专利材料）：①"探索性写作智能体"（S1）；②"多元角色互校验"（S2）；③"报告结构的人机协同建构"（S3）。
- **技术总基调（多次达成共识）**：不追求"引擎自动判得多准"，而是**把关键决策交给用户点选 + 事后独立校验**——这既契合现架构，又直接绕开"AI 判不准"的根因。

## 二、盲测评分结果（5 篇样本）

> 评分档：**1**=能直接用（改都不用改可提交）；**2**=可供参考（可细分 2+/2−）；**3**=不能用。C、E 为人写，A、B、D 为 AI 写（盲测揭盲）。

| 样本 | 主题（推断） | 作者 | 综合印象 |
|---|---|---|---|
| **A** | 人工智能+教育国际比较（AI 一版） | AI | 偏弱，框架维度"不是想看到的"，需重组（多人打 3 / 2−） |
| **B** | AI 写 | AI | 普遍 2 |
| **C** | 人工智能+教育国际比较报告（顶层设计/实施机制） | **人** | 政策意识最强，主创打 1、余多为 2+ |
| **D** | 终身教育趋势研判 | AI | "眼前一亮"，普遍 2+ |
| **E** | 中美 AI 人才竞争及应对策略 | **人** | 最完整，多人 1 / 2+，可直接用微调 |

**关键信号**：AI 稿里 D（终身教育）、B 表现尚可，但**没有一篇稳定压过人写的 C、E**。这确立了后续所有改进的"要打的靶"。

## 三、"好报告"的共识标准

会议显性说出的"好"，被 S11 评分 rubric 直接采纳为打分维度：

1. **真实可溯源**——每条有对应材料与网站链接，不胡说（底线）。
2. **问题意识**——从一个明确问题出发去解决，而非泛泛综述。
3. **站位/对象意识**——"顶天立地"，明确写给谁看（国家领导/教育部/司局）。
4. **观点鲜明、逻辑清晰、语言精炼准确**。
5. **维度有逻辑**——分析有维度且维度间有逻辑（如宏观/中观/微观、举措→趋势→机遇挑战），不是单一罗列。
6. **第一眼抓人**——领导"三五秒/翻三下"就能判断，题目一看就知行不行。

### 🔴 S1 + S4 + S6 · 写作前"探索性追问 / 类型识别 / 关键问题清单"

**会议诉求**：用户只有模糊主题时，智能体先**预检索**部分资料，再凝练几个候选研究问题让用户点选，然后才生成（像"深度研究"先追问再生成）；支持两条路线——①问题已明确→直接生成，②仅有兴趣领域→追问聚焦。同时把"目标读者/研究目的与类型/核心观点/维度逻辑/风格"固化成**关键问题清单**，第二步凝练成选项点选，第三步一步生成。报告类型（借鉴/趋势研判/应对型）当前"能自动判但判不准"（如"国际 AI 战略比较"被误放进经验借鉴）。

**现状（代码）**：
- report-type **完全靠人在启动 CLI 前手动指定** `--report-type`（默认 `strategic_response`，`strategic_response_workflow/workflow/runner.py:56/1048`），选型实际发生在**代码之外**——`report-workflow-runbook/SKILL.md` 是一张"题目→体例"的人工查表。**没有任何自动分类器**。
- 16 步流水线**全自动、零交互**（无 `input()`）；`redefine_task` 只是 LLM 内部把题目改写成判断句，**用户不参与、不点选**，且在检索之后。
- S6 的清单要素（读者/文体/维度/风格子型）**各自存在于 prompt 里**，但从不作为清单向用户点选。
- **可复用现成机制**：`topic-material-search` 已实现"预检索 + 与用户共创搜索计划（AskUserQuestion 多选）"，且其料包可被主流水线 `--reuse-materials-run` 直接吃。

**差距**：缺"仅有兴趣领域"这条路线的入口、缺预检索追问步、缺"用户选类型/选关键问题→回填 module 与 planning"的通路。

**修改方案（推荐 A 层 MVP，不改引擎）**：
1. 新增一个**「写作前澄清」技能**（或扩 `report-workflow-runbook`），由在场编排 agent 用 **AskUserQuestion** 完成：预检索（复用 `topic-material-search` 浅采集）→ 凝练 3–5 个候选研究问题（每个标注契合哪种体例）→ 呈现**5 问清单**（Q1 目标读者层级 / Q2 研究目的与类型=report-type / Q3 核心观点 / Q4 维度逻辑 / Q5 风格子型）→ 用户点选 → 拼成完整命令启动现有 16 步。
2. 新增 prompt `report_modules/_shared/prompts/clarify_scope.md` 承载"路线判定 + 候选问题 + 5 问清单"的生成逻辑（要点：证据不足如实标注、不硬凑；拿不准走追问）。
3. **类型识别改为"预检索证据→建议默认项→用户点选确认"**，自动判只做预填、用户拍板——直接绕开"判不准"。
4. 点选结果回填：Q2 选项**就是 report_modules 目录名**，直接作 `--report-type`；Q1/Q3/Q4 凝成 `clarify_decision.md`，经现有 `institution_profile` 注入通道进 planning（几乎零改）。
5. **B 层增强（二期）**：把 `clarify_scope` 固化为引擎正式预步骤（插在 retrieve 之前），用 handoff/resume 机制承载暂停与归档，使澄清可复现、可审计。

**涉及文件**：新增 `报告写作前澄清/SKILL.md`、`report_modules/_shared/prompts/clarify_scope.md`；复用 `topic-material-search/SKILL.md`、`institution_profile.md` 注入通道（均不改代码）。二期改 `strategic_response_workflow/workflow/runner.py`（加 clarify 步 + Config 字段 + 续跑分派）。

**工作量/风险**：MVP **1–2 天**（不碰 Python，零回归）。最大风险=**人机交互如何在自动 CLI 架构里落地**——A 层把交互放在"启动命令之前"（agent 用 AskUserQuestion），CLI 仍全自动，风险最低。误判"问题是否已明确"→缺省走追问兜底。

**优先级**：🔴 **最高**。一个 MVP 技能同时命中 S1/S4/S6 三项、直击会议"最关键问题"，且零引擎回归风险。**建议第一个做。**

### 🔴 S2 · 多层级站位模拟 + 角色互校验（交办任务②，专利卖点）

**会议诉求**：决策报告要有"对象意识"——给国家领导/教育部/司局写，站位不同（宏观/中观/微观）；一篇好报告"高战略+落地"两极都要有；站位主要体现在**对策建议**部分。要内置**多角色模拟**可选/自动匹配目标读者，并做**角色互相校验**。担忧：一句话 role prompt 在长文里"后面就忘了"，需做成**独立角色 + 独立校验环节**。

**现状（代码）**：
- 站位的唯一载体是 `strategic_response_workflow/institution_profile.md`，但它是**"机构站位（教育研究机构）"，不是"读者站位"**——管的是"建议落在哪个域"，**没有"国家领导/教育部/司局"分层**，`Config` 里无任何 audience 字段。
- 好消息：它已被 `_with_institution_profile()` **在 5 个步骤重复注入**（redefine/plan/pool/priority/write）——"防长文遗忘"的注入骨架已存在，**缺的是注入内容里没有读者层级维度**。
- review **不检查"读者站位过低/对象错配"**。注意：现有 review.md 里的"对象匹配"指**政策作用对象**（顶尖科学家 vs 留学生），**不是报告读者层级**，两者必须区分。

**差距**：缺整个"读者层级"维度、缺显式选择通道、缺独立"站位校验"reviewer。

**修改方案（复用现成骨架）**：
1. **数据层**：新建 `strategic_response_workflow/audience_profiles/{national_leader,moe,bureau}.md`，每档写四段（该读者关注什么 / 对策落点的宏中微观权重 / 语气详略 / 站位过低过高反例）。`institution_profile.md` 不动（两者正交叠加）。
2. **注入层**：`runner.py` 加 `--audience-level` + `_with_audience_profile()`（gated，缺失即零变化），注入 redefine/plan/pool/priority/write **5+ 处**（多点重复=防遗忘第一重保险）。
3. **校验层**：新增 `reviewers/audience_alignment_scope.md`（独立"站位互校验"尺子：给国家领导写却全是司局琐碎=过低；给司局写却只有空泛口号=悬空），在 `runner.py` 的 `_SCOPE_SOURCES` 加一行即得一个**独立校验角色**（复用 handoff 机制，`--review-scope audience_alignment`）——这就是"多元角色互校验"卖点雏形（第二重保险）。
4. inline `review.md` 也加一条"读者层级站位匹配"维度（第三重保险，不依赖 handoff）。

**涉及文件**：新增 3 个 `audience_profiles/*.md` + `reviewers/audience_alignment_scope.md`；改 `runner.py`（配置/CLI/注入/scope 表）+ `report_modules/strategic_response/prompts/{review,planning,suggestion_pool,policy_priority,writing}.md`。

**工作量/风险**：MVP **1–1.5 天**。核心风险=**三档站位内容要写准**（可从 gold_samples 里"国家领导型 vs 司局型"样本反推），以及 review 里"读者站位"与"政策对象"两概念措辞上彻底分开。MVP 阶段强制**显式选层级**，不做自动匹配（选错会把整篇带偏）。

**优先级**：🔴 高（交办②）。"独立角色 + 互校验"在本仓有现成骨架，主要工作是写准站位内容。

### 🔴 S11 · 评价标准显化为"评分→意见→返修"门控闭环（交办任务①）

**会议诉求**：把专家心中的隐性评分标准**显性化**为审核提示词，实现"生成→自动评分→给意见→返修→再评分…直到超过某分才输出"。评分档对齐 1/2/3。

**现状（代码，关键发现）**：
- 现状**不是评分门控循环，而是"审一遍→改一遍→定稿"的单遍流程**。达标判定门 `_review_reaches_standard` **已在一次重构中被删除**（`runner.py:758` 留墓碑注释，`_review_revise_loop:162-190` 现只跑一轮），`max_iterations` 参数空转。
- 旧门也只是**二元正则匹配**（匹配"总体结论：达到/未达到"等词），**从来不是数值分数**。
- `review_scope.md` 开宗明义"**只审文风和表述，不核查事实对错**"，**无维度评分、无权重、无阈值**。
- **重大正面发现**：S11 想要的东西**代码里 80% 已存在，只是散在实验脚本**——`workflow/tmp_ds_score_clarified.py` 已实现"7 维各 1–10 分 + 总分/70 + 等级门槛"的单篇打分器；`_revise_article` 已能吃审查意见返修。**差的正是那个被拆掉的"门"。**

**差距**：缺一份把会议 6 条标准落成"可打分维度+权重+目标分"的 rubric；review 需输出结构化分数；需重建"总分≥阈值且无硬伤→停，否则返修"的门控循环。

**修改方案**：
1. 新增 `strategic_response_workflow/policy_style_dna/quality_rubric.md`——把会议 6 条标准落成 6 维打分表（真实可溯源 20 / 问题意识 15 / 站位对象 15 / 观点逻辑精炼 20 / 维度逻辑 15 / 第一眼抓人 15），每维 1–10，加权归一百分制；**分档对齐会议 1/2/3**（1=≥85 且零硬伤 / 2=70–84 / 3=<70 或任一硬伤）；硬伤集（材料外露、对象错配、语域超标、伪比较罗列）任一命中强制判 3。
2. `report_modules/*/prompts/review.md` 输出要求追加**结构化 JSON 分数块** `{"dimensions":{...},"total":N,"grade":1|2|3,"hard_faults":[...]}`。
3. `runner.py` 新增 `_review_score()` 解析分数，把 `_review_revise_loop` 改回真循环（`total≥阈值 且 hard_faults 为空` 才 break，否则带意见 revise 再评，`max_iterations` 兜底）。**用 JSON 解析，不要退回脆弱正则门。**

**涉及文件**：新增 `quality_rubric.md`；改 `report_modules/strategic_response/prompts/review.md`、`workflow/runner.py`；可选改 `review_scope.md`、`reviewers/instruction_template.md`。

## 七、需要向会议澄清的 4 个认知偏差

> 这几点是 agent 读代码后发现的"会议印象 ≠ 代码现状"，建议展示时主动澄清，避免下轮重复讨论。

1. **文风"硬性对仗"其实不存在（S7）**：现规则不但没要求对仗/排比，`review_scope.md` 早已把"为对仗而对仗"列为扣分项。会议见到的"怪对联"是模型输出观感，或来自一个**不生效的死目录** `style_dna/`。真正要补的只有"语义去重"一条。

2. **"可溯源"在材料层成立、成稿层不成立（S9）**：成稿正文被**主动清洗掉引用序号、不带网站链接**，链接只在 `retrieval_outputs/` 材料层。"每条有链接可溯源"目前是"能回材料查"，不是"点链接直达"。若要成稿带链接，需另存"溯源版"。

3. **NotebookLM = Google，是唯一实打实的"非国产/出境"点（S10）**：主写作链确实 100% DeepSeek，但主检索走 Google NotebookLM。若"百分百安全全国产"是硬指标，需用 `topic-material-search`（国产源）或国产知识库替代。

4. **SKILL 并不"粗线条"（S5）**：16 步 + 每体例 10 prompt + reasoning_dna 判断刀 + 与金样本对比，细步骤已很密；"按类型分流"（借鉴/趋势/应对三体例）也已实现，且 `distill-report-module` 已能从范文批量造新体例。约 60% 是"看不见"的沟通问题，可视化即可大幅缓解。
