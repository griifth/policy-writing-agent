2. "下游问题几乎全是蒸馏方法缺陷的投影"成立——修方法（schema 前置/SSOT/引用/对账/盲测）确实能一次根治大半。

### 1.2 需要修正/补强的 8 处

**修正① B1 密钥问题降级（blocker → medium）。已核实：`.env` 从未进过 git。**
`git log --all --diff-filter=A -- "**/.env"` 为空；`.gitignore` 第 1 行即 `.env`（无斜杠模式，覆盖两处目录）；`git ls-files` 只跟踪 `.env.example`。《清单》B1 说"明文写入**被 git 跟踪风险**的 .env"——风险未成真。**处置**：不必按泄露应急处理；建议例行轮换一次密钥、在两处 `.env.example` 加注"密钥勿入库勿截屏"即可。别让 Opus 把时间花在"清洗 git 历史"上。

**修正② D-2（"必须/立即"消歧）的仲裁方案要改：单一证据级闸门会丢掉体例维度，应改为"双钥门"。**
《耦合专项》建议"以推理的证据级为唯一闸门，review_scope/subtype_a 引用它"。但这丢了一个真实约束：**子型 B（趋势研判）无论证据多硬都不用对攻腔**——文章 D 全篇 E3/E4 级证据仍是冷静单声部，这是体例属性不是证据属性。正确模型：
> **语气档位 = min(子型语域上限, 证据级强度准入)**。子型定"这类报告最高能说多狠"（A 可达强命令式，B 封顶建设句）；证据级定"这句话有没有资格说这么狠"（对攻腔需 E4/A 级）。两钥同开才放行。
落点：定义一次于 `shared_schema/strength_gate.md`（阶段 2 建），`subtype_a.md:12`、`review_scope.md:13`、`hedge.md:32` 三处全部改为引用。附判例三则（子型A+E4→"必须"可用；子型A+E2→降级为"应/宜"；子型B+任何级→建设句）。

**修正③ 证据分级统一（R-I1）必须先点名"测量对象"差异，否则统一后还会打架。**
①级语义相反不是笔误，是三把刀在量**不同的东西**：threat/signal 量"对手动作/趋势的**落地成熟度**"（已运行=最强），efficacy 量"效果的**被证实程度**"（有评估=最强），intent 量"意图的**明示程度**"。若只发一套裸量表，各刀还会各自解读。改法：`shared_schema/evidence_maturity.md` 给一套**具名四级**（E1 意图宣示 < E2 制度建成 < E3 运行数据 < E4 效果评估），并附一张"各刀测量对象注记表"（每把刀一行：本刀用该量表衡量什么对象），各刀正文删本地量表、只留 5–10 行侧重注记。

**修正④ 金样本 provenance 纪律与"D 作 trend gold"自相矛盾，需分层。**
M-I5 立了"DNA 只从人写金样本蒸馏、AI 稿只作 foil"，§五又推荐"趋势研判 gold → 文章D（AI 写）、文章B 作对位句式辅助"。两条打架。裁决：**按蒸馏对象分层**——
- **文风/语言蒸馏：human-only 硬门**（AI 腔污染主要发生在语言层）；
- **推理骨架蒸馏：允许用 AI 稿，但须 ①标注 `provenance=AI`、②剥离/占位符化全部精确数字、③只抽方法动作（光谱/反例/降级/分层），禁止抽句式**。
把这条写进 M-I5 的落地文本，否则 Opus 执行时无所适从。

**修正⑤ "include 原语 + CI 报错"要落地成本最低的具体机制——本仓没有 CI，且 Windows 移植在册，不能用软链。**
三份文件多处写"CI 加检查""另一份改软链"。现实：仓库无 CI；`WINDOWS_MIGRATION_CHECKLIST.md` 说明 Windows 部署是真实需求，symlink 在 Windows 上是坑。落地方案改为：
- **include 机制**：在两引擎各自唯一的 DNA loader（`workflow/report_pipeline.py:_policy_style_dna_text` 与 `strategic_response_workflow/workflow/runner.py:_policy_style_dna_text:808 / _reasoning_dna_text:844`）里做 `{{include:相对路径#锚}}` 文本展开——各约 15 行代码，无新依赖；
- **检查机制**：新建 `tools/check_dna.py`（重复检测：跨文件 8-gram 重叠超阈值报警；悬空引用检测：include/文内路径必须存在；canonical 唯一性：登记表外出现同名 DNA 文件即报错），挂进现有 `scripts/deploy_selfcheck.py` 与 runner 启动自检，替代"CI"。
- **双份消除**：不用软链，直接**唯一目录 + 两引擎 loader 改常量指向它**（见阶段 1）。

**修正⑥ 两张路线图必须合并——方法治理 P0 与会议功能 P0 有同文件竞争，分开跑会互相踩。**
《蒸馏方法评估》的 P0（schema/SSOT/修锚）与《会议评估》的 P0（S1 澄清/S11 评分门/S2 站位）各排各的，但 S11 的 quality_rubric、评分门与本次交付的终审人落在同一批文件（review.md / runner 审改循环 / review_scope），S2 的 audience 校验也要挂同一个 `_SCOPE_SOURCES`。**合并原则**：先做"改一处、稳全局"的地基（修锚+SSOT 收敛），再做同文件簇的功能（评分门+终审人+scope 接线一批做完），最后做交互功能（S1/S2）。见第四部分六阶段序列——它就是合并后的唯一执行序。

**修正⑦ A7（成稿无链接）的定性要按体例纠偏：正文无角标不是缺陷，是内参体例的合规要求。**
jiaokeyuan-researcher 群像明确：课题组研究报告体"**不加角标、文末不列引用**，政策文件在正文内以中英文全称＋年份就地标注"。金样本 C/E 正文同样无链接。所以 A7 的问题不是"正文没链接"，而是**（a）零程序化溯源校验（真缺口，blocker 维持）＋（b）没有归档用溯源版**。解法即会议 S9 双轨：提交版干净（体例合规）＋ `final_article_sourced.md` 归档版带源 ＋ `citation_audit.py` 导出前硬校验。别让 Opus 去改写作契约往正文塞链接——那会同时违反体例与金样本。

**补强⑧ 根引擎需要一个"终局"决策（三份文件都没给）。**
盲测给了实证：同题对照下，**根引擎产的 A 是五篇最弱**（2−/3），战略引擎产的 B/D 均达 2/2+——差距恰好是根引擎缺的推理 DNA/体例架构（H1/D6）。三份文件只列"能力不对齐"，没给终局。我的建议：**把"国际比较"移植为战略引擎第 4 个体例 `report_modules/international_comparison/`（用 `distill-report-module` skill，以文章C 为 gold、文章A 为 foil），跑通同题盲测平价后冻结根引擎（归档不删）**。一次消掉 H1、D6、C1/G1（双份 DNA）、G2、G4 的一半问题。时点：7 月底试合之后做（阶段 6），试合前不动根引擎。

## 二、样例人机差异——独立判读（对《蒸馏方法评估》§五的验证与补充）

我逐篇精读了 5 篇样例（文本版已转出至 `method_audit/samples/txt/`）。§五的盘点结论**全部得到验证**，另有 6 点补充，直接影响审批者与蒸馏的设计：

**① C 胜 A 的关键不是证据量——A 的引证密度反而更高。** A 几乎每个文件都带中英文全称+日期，密度超过 C。差在三处：C 的分类是**双轴正交**（顶层设计三型 × 实施机制三型，回答"谁定的+谁在干"两个决策者真问题），A 单轴（三型）后第二节漂移到"教育主体性"这个学术主题——会议说"框架维度不是想看到的"指的就是这个；C 有**证据甄别**（"澳大利亚该文件虽名为'框架'……严格意义上不能看作为政策规划"——主动对材料降级），A 对所有材料照单全收；C 每国一段、段长克制，A 惯用 800–1000 字巨型混排段，"翻三下"测试直接失败。**启示：审批者判研判深度，看"有没有对材料说过不"比看"引了多少料"更灵。**

**② E 胜 B 的关键在史料纵深与抓手具体度。** E 用 1958《国防教育法》做条款级古今对照（十条52款、经费14倍、三条延伸判断），B 只把 NDEA 当"先例"一句带过；E 的对策全是制度杠杆级（职称评审单列/中考必考科目/科学家驻校/淡化人才帽子/移民签证调整），B 的对策方向对但杠杆软。B 还有两处 AI 指纹：每条建议逐字同构的"针对美方X…建议Y…"脚手架；关键论断用"据公开报道/据相关战略文件披露"弱引源。

**③ D 证明推理刀真的有效，同时暴露最大风险点。** D 的成熟度光谱、反例陷阱（日本"形式制度化"）、证据降级（美社区大学→局部探索）、对策三期分层——方法动作完整度五篇第一，会议"眼前一亮"是真的。但 D 每条建议同构起笔（"直接回应X…/回扣X…"×9 条）暴露脚手架，且全篇 20+ 个精确数字（1.64亿/2223万/447个/75家/8.2万/6.8万/0.72/33.1%…）**密度超出人写基准、真伪待核**——这是 AI 精确数字幻觉的典型形态。修法不是删数字，是 citation_audit 程序核 + 写作契约里加"数字须有材料命中，无命中降级为量级表述"。
**④ 人写≠零瑕疵，gold 入库前也要清洗。** C 有张冠李戴（爱沙尼亚项目写成"爱尔兰教育和研究部"牵头）、错别字（"个人数据据""师生素AI素养"）、加粗错位（"四**是**"）。两个推论：审批者不能把"零笔误"当人写判据（已写进 scope 的反向校准条）；C 作为蒸馏 gold 前须先做一遍事实与文字清洗，否则把笔误蒸进 DNA。

**⑤ "人类签名 4 件套"（已固化进终审人第二遍）**：多轴分类 ｜ 证据甄别（对材料说"不"）｜ 史料/机制纵深 ｜ 制度杠杆级抓手。
**"AI 指纹 6 条"（已固化进终审人第三遍）**：巨型平铺段 ｜ 段末同构收拢 ｜ 建议脚手架同构 ｜ 弱引源顶关键位 ｜ 精确数字过密线索薄 ｜ 伪对仗语义重复。

**⑥ 五篇的档位锚点已写进 `quality_rubric.md` 第四节**（C=1、E=1、D=2+、B=2、A=2−），与会议盲测原始评分对齐。以后任何评委（LLM 或人）评新稿先问"最像哪篇"，能显著压评分方差——这直接服务 S11 的"阈值定标"。

## 三、文稿审批者：设计说明与用法

### 3.1 为什么这样设计

- **现状缺位**：现有审校是"维度检查器"（style_and_expression 只审文风、precedent_check 只查先例、reasoning_compliance 还没接线），**没有人扮演"这篇能不能报"的终审人**——而会议盲测评的恰恰是终审视角（1/2/3）。
- **角色来源三合一**：jiaokeyuan-researcher 的六范式与"诚实边界"（盲区自纠）提供**研究员怎么想**；金样本 C/E 的写作签名提供**好稿长什么样**；会议六条标准提供**打分维度**。三者分别落进三遍读法的第二遍、第三遍与评分环节。
- **严守层归属（不重蹈 R3/R4 覆辙）**：终审人**只新增**"终审判分、范式合格、站位核查、人机指纹"四件事；文风细则、证据纪律、落点规则一律引用不复述；分值全部指向 `quality_rubric.md` 唯一真源。这两份新文件本身就是按目标态（引用而非复制）写的，可作后续改造的样板。

### 3.2 两份资产怎么配合

```
quality_rubric.md（评什么分·唯一真源）
   ├─ 六维加权表（会议六条标准 → 1–10 分行为锚定）
   ├─ 硬伤集 H1–H6（只登记条目，细则指回各 canonical 属主）
   ├─ 1/2+/2/2−/3 分档 ←→ 达到/基本达到/未达到（与现有门控正则兼容）
   ├─ 盲测锚点表（A–E 五篇定标）
   └─ JSON 输出契约（供评分门解析）

reviewers/jiaokeyuan_review_scope.md（谁来评·怎么评）
   ├─ 第一遍 领导速读（三五秒/翻三下 → 维度6）
   ├─ 第二遍 范式六查（问题意识/矩阵类型/循证三件套/纵深/差距对策/盲区对冲 → 维度1–5）
   ├─ 第三遍 防伪六查（AI 指纹 → 压维度4/6）
   └─ 输出：总体结论行 + rubric JSON + 逐条"原文→问题→改法" + 终审意见书
```

### 3.3 三种用法

1. **引擎内 handoff 终审**（推荐为默认终门）：`--reviewer handoff --review-scope jiaokeyuan_final_review`——接线方法见阶段 3.4，交接指令由现有 `instruction_template.md` 自动渲染。
2. **引擎内 inline 自审**：评分门恢复后（阶段 3.3），rubric JSON 直接驱动"达标才出、不达标带意见返修"循环。
3. **独立审改**（对应 jiaokeyuan-researcher 用法③）：把任意外来稿 + 两份文件喂给任意 agent 即可出终审意见书——7/13 演示可现场表演这一手（审一篇在场专家带来的稿）。

### 3.4 与 S2（读者站位）的关系

终审人查"站位与对象"是**判分**（rubric 维度 3 + 硬伤 H6）；S2 的 `audience_profiles/` 是**数据层**（告诉写作侧"给谁写该怎么写"）。互补不重复：S2 建成后，终审人第二遍第 1 查自动引用所选 audience profile 作对照基准（scope 文件已预留"引用不复述"结构，届时加一行引用即可）。
