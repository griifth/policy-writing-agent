# 工作流技术审查 01：从"检索材料"到"文章主体"的材料组织环节

- 审查对象：`strategic_response_workflow`，`experience_response` 体例（当前主用）
- 审查焦点：把零散检索材料**重新整理成有结构的正文叙述**这一环节，是否有专门一步在做；它如何决定后文"中国应对建议"的事实地基
- 证据来源：`workflow/runner.py`、`report_modules/experience_response/prompts/*`、`module.yaml`、真实运行 `runs/run-20260623-151123-50592bc4/`（主题：美英德澳体育教师培养与聘任）
- 结论先行：**不存在一个名为"材料组织/重述"的独立步骤**；材料的"判断性组织"被分散塞进了判断步（material_roles / pressure_judgment）和构思步（planning），而把它**落成正文叙述**这件事（重述层）则被隐式甩给了写作步（writing.md）临场处理。本次 run 因为 planning 产物异常厚实，正文质量没塌；但这是**靠某一步超额发挥兜住的，不是流程结构保证的**——这正是薄弱点所在。

## 一、流程拆解（材料视角）：材料 → 文章各部分的实际链路

`runner.py` 的步骤顺序（`TASKS`，行 28-45）与各步对"材料"做的事如下。每一步喂入什么、对材料做何变换、落到哪个文件，逐步对照如下表（步方法见 `runner.py` 对应行）：

| 步 | 方法（行） | 喂入的上游 | 对"材料"做的变换 | 产物文件 |
|---|---|---|---|---|
| 检索拼装 | `_build_retrieval_prompts`（371） | retrieval.md 模板 + 通用变量 | 按 6 类检索任务各拼一份提示词 | `generated_prompts/retrieval_*.md` |
| 检索 | `_retrieve_materials`（380） | NotebookLM / 复用 | 把知识库内容按 6 类抓成**带证据状态标签的条目清单** | `retrieval_outputs/{6类}.md` |
| 重定义 | `_redefine_task`（396） | 全部检索材料 + 模板 | 把题目变成"可写作的判断问题"，**不动材料本身** | `judgment_outputs/task_redefinition.md` |
| 材料角色 | `_assign_material_roles`（412） | 重定义 + 全部材料（+efficacy 刀） | 给每类材料**贴角色标签 + 证据状态 + 降级说明**（不重排叙述） | `judgment_outputs/material_roles.md` |
| 压力-判断 | `_map_pressure_judgment`（429） | 重定义 + 角色 + 全部材料（+cause 刀） | 把零散做法**抬高一层成 3-6 组"做法→判断"**，并做互证/可照搬扫描 | `judgment_outputs/pressure_judgment_mapping.md` |
| 构思 | `_plan_article`（447） | 模板 + 重定义 + 角色 + 压力判断 + 全部材料（+刀） | **把做法归并成 2-3 种模式、列二级判断、设计每章功能与推导链** | `planning_outputs/article_plan.md` |
| 建议池 | `_build_suggestion_pool`（470） | 重定义 + 角色 + 压力判断 + 构思 + 全部材料 | 把判断推成**候选建议表（含借鉴来源 + 迁移前提）** | `suggestion_outputs/suggestion_pool.md` |
| 优先序 | `_prioritize_policy_options`（493） | 重定义 + 压力判断 + 建议池 | 给建议排近期/中期/长期 | `suggestion_outputs/policy_priority.md` |
| 写作 | `_write_draft`（512） | 文风 DNA + 模板 + 构思 + 重定义 + 角色 + 压力判断 + 建议池 + 优先序 + **全部材料** | **把以上全部一次性融成正文**——组织材料、写判断、控文风同时发生 | `drafts/current_article.md` |

关键结构事实（来自 `_write_draft`，行 512-540）：**写作步把"构思 + 三份判断产物 + 建议池 + 优先序 + 全部原始检索材料"一起喂进同一个提示词**，让 LLM 当场决定哪段材料进哪一章、怎么叙述。也就是说，"材料如何被组织成正文的字句"这一步，没有任何中间产物，直接发生在写作步内部。

**实际链路图（材料视角）：**

```
retrieval_outputs（6类带证据状态的条目清单）
        │
        ├─→ material_roles      贴标签：主/辅角色、证据状态、降级清单（不重排叙述）
        │        │
        ├─→ pressure_judgment   抬一层：3-6组"做法→判断"、模式雏形、可照搬扫描
        │        │
        ├─→ planning            归并：2-3模式 + 二级判断 + 每章功能 + 推导链 + 标题结构
        │        │                （← 本次 run 真正做"材料怎么进每章"的地方，但产出的是"判断地图"，不是"正文叙述"）
        │        │
        │        └─→ suggestion_pool → policy_priority   （建议从判断里长出来）
        │                                  │
        └─────────────────────────────────┴─→  writing.md（写作步）
                                                  │  ← 此处第一次、也是唯一一次
                                                  │     把"组织好的判断"+"原始材料"落成正文字句
                                                  ▼
                                          正文 第一/二部分 + 建议部分
```

## 二、"材料组织"到底发生在哪一步、由谁负责？

**答案：没有专门的"材料重述/组织成叙述"步骤。它被拆成两半，各自残缺。**

1. **"判断性组织"（材料该归成几类、谁证明谁、哪条降级）** 分布在 `material_roles` 和 `pressure_judgment`、并在 `planning` 收口。这部分做得相当充分——见第三节证据。
2. **"叙述性组织"（把组织好的判断落成连贯正文段落、决定每段先说哪句证据后下哪句判断）** 没有独立步骤，**被隐式合并进写作步**。`runner.py:_write_draft` 同时塞进"判断产物 + 原始材料 + 文风 DNA + 模板 + 建议池"，让写作步一次性完成"组织材料 + 写判断 + 控文风 + 排优先级"四件事。

换言之：流程**不是**"判断产物 → 重述层 → 写作"，而是 **"判断产物 + 原始材料 → 直接写作"**。中间缺的正是用户担心的那一层——把检索材料**重排、剪裁、缝合成指向判断的证据流**的"材料重述层"。

一个佐证：在 `report_modules/experience_response/prompts/` 全目录 grep "重述 / 叙述 / 重新整理 / 材料组织"，**无任何命中**。流程里没有任何一步以"组织材料叙述"为单一职责。`material_roles.md` 开篇甚至明确把自己的职责限定为"判断每类材料证明什么，**而不是平均摘要材料**"（行 5）——它**主动声明自己不做叙述重排**，只做贴标签。

## 三、薄弱点定位（用真实产物作证）

### 薄弱点 A：material_roles 只"贴角色标签"，不"重排叙述"——按字段填表，不产出可读叙述

`material_roles.md` 提示词第 17-32 行规定它"从角色标签里多选、分主次"，输出"材料角色总表 / 材料互证关系 / 降级使用说明"。真实产物 `judgment_outputs/material_roles.md` 正是**一张表**：

> | 材料名称/检索类别 | 主角色 | 辅角色 | 核心命题 | 可支持的判断 | 证据状态 | 不能承担的任务 | 优先使用章节 |
> | `key_practices` | 做法范例 | 比较参照 | 四国在"资格准入—职前培养—认证注册"环节形成了四种模式… | … | 已实施 | 不能直接证明有效性 | 第一部分 |

这一步的价值是**给材料定性、划证据状态、标降级**（很重要，是事实地基的"质检"），但它的输出形态是**字段化的表**，不是"可读叙述"。它告诉下游"这块材料配进第几章、能证明什么"，但**没有把材料缝成一段话**。提示词质量要求里(行 62-66)四条全是"不得平均摘要 / 必须标证据状态 / 不能支撑就降级"——全部是**定性纪律**，没有一条要求"重排成叙述"。

### 薄弱点 B：planning 偏"判断地图 / 章节功能"，给的是"每章推进什么判断"，不是"材料如何组织进每章的字句"

`planning.md` 第 54-62 行的"章节功能设计"要求每章说明"标题建议 / 负责推进的判断 / 主要证据 / 如何引出下一章"。真实产物 `planning_outputs/article_plan.md` 严格照此输出，例如第三章：

> **第三章：成因与效度：做法背后的体制根源与证据检验**
> - **负责推进的判断**：这是全文从"做法陈述"到"经验判断"的关键一跃……
> - **主要证据**：`enabling_conditions`解释成因；`effectiveness_evidence`（RCT、研究综述、统计数据）判断有效性……

这是一份**优秀的"判断地图"**——它定义了每章的论证功能、归并出"专业化保障 / 应急补充"两模式、画出三条推导链。但请注意它给的颗粒度：是"这章用哪几类材料推进哪个判断"，**不是**"这章第一段先摆 LOOK 研究的 6.5 分钟、再下'专科教师不可妥协'的判断、再用德国 50% 反证"。**它组织的是判断的骨架，不是叙述的血肉。** 从骨架到血肉的那一跳，仍留给写作步。

> 重要限定：本次 run 的 `article_plan.md` 长达 134 行、异常厚实，"模式归并 + 二级判断 + 材料互证 + 推导链"都做到了。**正文第一、二部分质量没塌，主要是这份 planning 超额兜住的**——正文"一、两种模式的谱系""二、成因与效度"几乎是 planning 里模式划分与二级判断的散文化展开。**但这是 planning 这一步替缺失的"重述层"加了班，不是流程有专门环节保证。** 换一个 planning 产出偏薄、或写作步 token 预算吃紧的 run，这层兜底就没有了。

### 薄弱点 C：writing.md 负担过重——一步内同时"组织材料 + 写判断 + 控文风 + 排优先级"

`_write_draft`（`runner.py` 行 512-540）一次性注入 9 大块上下文（文风 DNA、模板、构思、重定义、角色、压力判断、建议池、优先序、**全部原始检索材料**）。而 `writing.md` 给这一步压了 **21 条总原则 + 输出要求 + 4 段结构指引 + 文体要求 + 段落功能要求**。其中：

- 行 16："必须区分证据状态……仅试点/意图/媒体转述的应写成'做法/动向'" ← 这是**材料降级**职责
- 行 24："材料应服从论证链，不能让文章退化为材料摘要" ← 这是**材料组织**职责
- 行 9-11："归并为 2-3 种模式 / 先做法后成因再现状最后建议" ← 这是**叙述结构**职责
- 同时还要管 AI 腔、英文缩略词密度、标题字数、加粗领起句、迁移前提……

也就是说，**"把材料组织成叙述"只是写作步众多并列任务之一，且排在文风、结构、建议合理性等一堆约束之后**。当一步要同时满足二十多条约束时，"材料如何缝成指向判断的证据流"很容易被降格为"按结构指引把材料摘要填进对应章节"。本次靠 planning 兜住了；但这是把一个本应前置、专门处理的工序，压在最末端、最拥挤的一步里临场完成。

### 薄弱点 D：检索产物 → 正文之间没有"材料重述层"中间产物

`judgment_outputs/`、`planning_outputs/`、`suggestion_outputs/` 三个目录里，**没有任何一个文件的产物形态是"组织好的、面向正文的材料叙述"**。它们分别是：角色表、判断列表、章节功能地图、建议表、优先序。从这些"判断态"产物，到正文"叙述态"文字，中间没有落盘的中间态。这意味着"材料怎么被叙述"这件事**在流程里不可见、不可单独审查、不可复用**——它只存在于写作步的黑箱里，只能事后审 `final_article` 成品，无法在写作前就检查"材料组织对不对"。

## 四、影响链：材料组织薄弱 → 建议悬空

把因果链讲清楚（这正是用户的核心关切）：

1. **建议依赖前文事实地基。** `writing.md` 行 84 硬性要求："每条建议都要能在前文找到明确依据，并指明借鉴了哪条经验。" 也就是建议的合法性，来自正文第一、二部分**已经把材料组织成的"指向判断的证据结构"**。
2. **如果材料在正文里只是被平均摘要、逐国罗列**，那么第一、二部分给出的就不是"证据结构"而是"资料汇编"。建议向上回指时，找到的是一堆并列事实，而非"X 做法在 Y 条件下有效→中国前提是否成立"的判断阶梯。
3. **结果：建议悬空、泛化、缺乏事实支撑。** 建议会退化成"加强、完善、推动"式空话（`planning.md` 行 77 与 `writing.md` 行 18 都点名要防的失败态），因为它脚下没有被组织好的证据可踩。

**本次 run 是这条链的"正面案例"——恰恰证明了组织环节的决定性：** 因为 planning 把材料组织成了"模式 + 二级判断 + 推导链"，建议池 `suggestion_pool.md` 才能产出每条都带"借鉴的做法/经验"列 + "迁移前提（是否成立/需先补什么）"列的表：

> | 建议2 开辟"先上岗、再达标、持证同级"柔性通道 | 借鉴：英"多入口严出口"逻辑；德"横向进入"常规化导致专业化低的**反面教训** | 迁移前提：**不完全成立**……必须先完成建议1的标准研制 |

这条建议之所以**没有悬空**，正是因为它能精确回指到 planning/pressure_judgment 里组织好的"德国反面教训"和"英国严出口判断"。**这反向证明了：建议质量与材料组织质量强相关。** 本次链条没断，是因为有一步（planning）超额做了组织工作；一旦那步退回提示词的"标准动作"水平（只产判断地图、不深做模式叙述化），或写作步被文风/结构挤占，建议就会失去这层可回指的证据结构而悬空。**风险不在"本次坏了"，而在"靠运气好的某一步兜着、没有结构性保证"。**

## 五、改进方向（初步，点到为止）

给三个候选方向及利弊，不展开实现。

### 方向 1：新增独立的"材料重述 / 证据编排"步骤（material_synthesis）

在 `pressure_judgment` 之后、`planning`（或 writing）之前插一步，单一职责：**把判断产物 + 原始材料，重排成面向正文第一、二部分的"证据叙述块"**——每个块 = 一个判断领起句 + 按证据状态排序的证据流 + 反证边界，落盘为 `judgment_outputs/material_synthesis.md`，再喂给写作步。

- 利：把"材料如何叙述"从写作步黑箱里**显式化、可审查、可复用**；写作步卸下组织重担，只做散文化与文风；正文证据结构不再依赖某一步超额发挥。直接命中用户说的"缺一层材料重述"。
- 弊：多一次 LLM 调用与一份产物，链路变长；与 planning 的"章节功能 / 材料互证"职责有重叠，需划清边界（planning 管骨架与章节分工，synthesis 管每块的叙述编排），否则两步互相打架。

### 方向 2：强化现有 planning / material_roles，不新增步骤

让 `material_roles` 在角色表之外，**追加"每条材料的一句话叙述定位"**；让 `planning` 的"章节功能设计"从"负责推进什么判断"下沉到"**本章按什么顺序摆哪几条证据、用哪句领起、用哪条反证收口**"。

- 利：不改流程结构、不加调用，改动最小，风险低；把本次靠 planning 兜底的隐性能力**写进提示词显性要求**，让它从"偶发"变"必然"。
- 弊：进一步加重 planning/material_roles 的提示词负担（material_roles 已要管角色+证据状态+降级+互证）；"叙述编排"塞进"判断产物"里，产物形态混杂，仍不是独立可审的"重述层"；治标不治本——写作步同时干四件事的拥挤问题没解决。

### 方向 3：加一把 reasoning_dna 的"刀"——材料编排刀（material_ordering / 证据流刀）

仿照已有 `efficacy`（有效性刀）、`cause`（成因刀）的形态，给写作步（或新 synthesis 步）注入一把"**叙述编排刀**"：逼问"每个分析段是否做到'判断领起句 → 按证据状态排序的证据 → 反证边界'，而非平均摘要 / 逐国罗列"，并要求留下"哪些材料被降级为背景、哪些升为主证"的可核对取舍记录。注入点写进 `module.yaml:reasoning_dna_injection`。

- 利：与现有 reasoning_dna 机制（`_with_reasoning_dna`，`runner.py` 行 821；`conventions.md` 的"降级扫描 + 留痕"红线）**完全同构**，是最小增量的能力补强；刀只逼判断纪律、不规定文体，正好治"材料被平均摘要"这个病根；gated 设计下缺刀零影响，可灰度。
- 弊：刀是"逼问"不是"产出叙述"——它能**逼写作步把材料组织好并留痕**，但**不替写作步卸载**组织负担，写作步仍要同时干多件事；若不配合方向 1 的独立步骤，刀的"留痕"会混在正文外的扫描记录里，可见性不如独立产物。

**初步取向（仅建议）：** 方向 3（编排刀）作为低成本即时补强先上，把"不许平均摘要、必须证据流"变成有留痕的硬约束；若要根治"写作步过载 + 重述层不可见"，再上方向 1（独立 synthesis 步）。方向 2 风险最低但天花板也最低，适合作为过渡。
