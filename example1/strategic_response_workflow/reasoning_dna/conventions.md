# reasoning_dna 元格式 · conventions（一把"刀"的统一形态）

> 所有 reasoning_dna 刀文件（各体例 `report_modules/<体例>/reasoning_dna/*.md`）都必须遵守本元格式。
> 改本文件 → 全体刀的形态约束随之变（共享基底，避免各体例反模版纪律漂移）。

## 一把"刀"是什么
不是文风（那是 style_dna），不是流程模板（那是模块 prompt）。
一把刀 = **一刀逼问**：逼模型在某个角度想透，并留下**可检查的取舍记录**。约束的是"必须想到哪几层、哪条判断必须留痕"，不规定文体。

## 强制三段式（每把刀文件必须有这三节）
### 必答问题
该刀的**领域无关元问题**（不绑定具体选题，如不得出现"AI人才""校园餐"等词）。
### 什么算答到了（含反例）
正例判据 + **反例**：明确写出"什么样的回答是糊弄 / 未答"。
### 降级扫描要求
必须执行的扫描动作 + 取舍记录格式（见红线）。

## 反模版红线（不可让步）
每刀产物必须是"**完成降级扫描 + 留下可审查的取舍记录**"，不是"写一段分析"。
- 要求**做扫描并给结论**；结论可以是"存在 N 处需降级"，也可以是"无需降级，因为证据满足 X"。
- 可检查的产物是"**扫描 + 结论 + 理由**"，**不要求强行造一条否定**（防止为凑格式制造问题）。
- 原理：注水只能增不能减；模版能造小节，造不出"我扫描后判 X 不降级、依据是 Y"这种可核对的取舍痕迹。

## 审查判据
查"**有没有发生过降级扫描并给出结论**"，**不查**"有没有对应小节"，**不要求**"必须有一条否定"。
探针：拿 1 篇金样本 vs 1 篇浅综述套这把刀 → 金样本应判"已答"、浅稿应判"未答/未做扫描"，区分得开。
