# 政策报告智能写作工作流 · 汇报方案（含架构图与流程图）

> 用途：本文档是 PPT 汇报的**内容底稿 + 核心图解**。可直接喂给 PPT 生成软件（Gamma / Marp / Slidev / 讯飞智文 等）——第三部分「逐页内容」按 `---` 分页、标题即页标题；第二部分的 mermaid 图多数工具可直接渲染，或据文字说明重画。
> 汇报时长约 15–20 分钟，14 页。

---

## 一、汇报主线（一句话版）

**痛点**：政策内参报告（国际比较 / 经验借鉴 / 趋势研判）写作耗时，且要保证"内参体例 + 战略高度"，人工难标准化。
**方案**：把它做成一套**可复用工作流**——三条路取料 → 两台引擎 + 可插拔提示词写作 → 教科院 skill 审核优化 → 成稿。
**证据**：已跑近百次（根 20 + 战略 77 = 97 次），产出多篇成稿，含教科院修订版。

## 二、核心图解（重点：讲清楚这几张图）

### 图 1 · 系统架构图（四层）

```mermaid
flowchart TB
  Q([研究问题 / 选题])

  subgraph L1[① 材料源层 · 三条路殊途同归]
    NB[NotebookLM<br/>自有知识库·现查现铺]
    WS[topic-material-search<br/>公网检索 + DeepSeek 复审]
    RU[复用料包<br/>--reuse-materials-run]
  end
  PACK[("统一料包<br/>retrieval_outputs/*.md<br/>二段式：检索内容 / 相关文献")]
  Q --> L1
  NB --> PACK
  WS --> PACK
  RU --> PACK

  subgraph L2[② 写作引擎层 · 两条骨架]
    E1[根引擎 workflow<br/>章节流水线 · 23 步<br/>国际比较]
    E2[strategic 引擎<br/>判断流水线 · 16 步<br/>3 体例]
  end
  PACK --> E1
  PACK --> E2

  subgraph L3[③ 注入提示词层 · 只控风格/判断/落点，不控事实]
    A1[文风提示词]
    A2[分析深化提示词]
    A3[战略高度提示词]
    A4[教育落点提示词]
  end
  L3 -. 注入 .-> L2

  DRAFT[("初稿<br/>runs/&lt;id&gt;/final_*.md + .docx")]
  E1 --> DRAFT
  E2 --> DRAFT

  subgraph L4[④ 审核优化层 · 教科院 skill]
    J1[jiaokeyuan-researcher<br/>审改整篇 · 合内参体例]
    J2[audit-extend-suggestions<br/>建议防重 / 补深 / 找空白]
  end
  DRAFT --> L4
  L4 --> FINAL([成稿])
```

**怎么读这张图**：从上到下四层。①材料无论来自自有库、公网还是复用，都收敛成**同一种料包格式**（这是解耦关键）；②两台引擎按题材二选一；③文风/判断/落点等提示词像"插件"注入引擎，只管怎么写、不碰写什么；④成稿再过教科院 skill 做体外精修。**一句话：材料标准化进、提示词可插拔、审核在体外。**

### 图 2 · 核心抽象：一套模块族 × 三个旋钮

```mermaid
flowchart LR
  subgraph MF[一套模块族]
    m1[检索] --> m2[构思] --> m3[写作] --> m4[审查] --> m5[改写]
  end
  K1[[旋钮1<br/>检索维度]] -. 调 .-> MF
  K2[[旋钮2<br/>分析深化提示词]] -. 调 .-> MF
  K3[[旋钮3<br/>文风子型/落点]] -. 调 .-> MF
  MF --> R1[strategic_response<br/>战略竞争应对]
  MF --> R2[experience_response<br/>经验借鉴]
  MF --> R3[trend_review<br/>趋势研判]
  MF --> R4[国际比较<br/>根引擎]
```

**怎么读这张图**：所有体例共用同一套模块族（检索→构思→写作→审查→改写），真正区分它们的只有**三个旋钮**——往哪几维检索、用哪条分析深化提示词、按哪种文风/落点落笔。**一句话：不是每个体例各写一套，而是同一套靠三个旋钮排列组合出多个体例。**

### 图 3 · 使用全景流程图（四阶段）

```mermaid
flowchart LR
  Q([研究问题]) --> S1[① 搜资料 + 检索成料<br/>研究问题拆成检索维度→取材料]
  S1 --> P[(料包 retrieval_outputs)]
  P --> S2[② 识别体例 + 跑写作引擎<br/>选 report-type → runner.py]
  S2 --> D[(初稿 final_*.docx)]
  D --> S3[③ 教科院 skill 审核优化<br/>jiaokeyuan 审改 + 建议核查]
  S3 --> F([成稿])
```

**怎么读这张图**：这是"人怎么用"的主线——四步，左到右。搜资料和检索问题是一件事的两面（先拆维度、再取料）；识别体例=选对 report-type；最后一步是体外精修。**一句话：搜料 → 成料 → 选体例写 → 审核优化。**

---

### 图 4 · 引擎内部运行流程图（一次运行发生了什么）

```mermaid
flowchart LR
  R[检索<br/>retrieval_outputs] --> C[构思<br/>分析深化提示词 + 战略高度提示词]
  C --> W[写作<br/>文风提示词 + 教育落点提示词]
  W --> RV[自审<br/>内容/结构审查]
  RV --> RW[改写<br/>据审查重写]
  RW --> EX[导出 docx]
  TS[["贯穿：task_state.md 记录每步进度<br/>断点可 --continue / --resume 续跑"]]
  TS -. 监督 .-> R
  TS -. 监督 .-> EX
```

**怎么读这张图**：`runner.py` 一条命令启动后，引擎内部自动跑这条流水；每步产物落盘、进度写进 `task_state.md`，中断能续跑。构思步注入"分析深化提示词+战略高度提示词"保推理深度与战略高度，写作步注入"文风提示词+教育落点提示词"保内参体例与教育域落点。**一句话：一条命令，内部自动走"检索→构思→写作→自审→改写→导出"，全程可断点续跑。**
