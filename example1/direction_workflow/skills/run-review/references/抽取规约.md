# 抽取规约：run 目录 → RUN_DATA JSON

> 配套：`skills/run-review/SKILL.md`（流程）＋ `skills/run-review/references/page_template.html`（页面，数据占位符 `/*__RUN_DATA__*/`）。
> 本规约是模板与生成器共同遵守的字段映射真源。路径约定：相对路径一律以 direction_workflow/ 为根。

## 〇、总则（三原则）

1. **候选文件名按序探测**：run 目录形制统一但文件名与细节格式随版本有变体。每类产物给候选文件名列表，按序取第一个在场者。
2. **容错不算错误**：任何文件缺失、任何字段解析失败，都不报错、不中止——对应字段留空/留空数组，记入 `extractionNotes`，页面相应位置显示"本单无此件"。**宁可标"推断"，不可默默填。**
3. **只读＋零编造**：对 run 目录只读；JSON 里一切实质文字抽自原文，不新写结论、概括、评价。推断产生的关联（只有 sections↔viewpoints 联动一种，见 §三）必须记入 `extractionNotes`。

## 一、数据模型（RUN_DATA 全字段）

```json
{
  "meta": {"runId":"", "title":"", "date":"", "panxing":"", "yongtu":"", "engine":"", "gouxuanlv":""},
  "direction": {"yiti":"", "jiantou":[], "duzhe":"", "jinqu":[], "zhijue":""},
  "sections": [{"id":"s1","heading":"","mainlineSeg":"","viewpointIds":["v1"]}],
  "viewpoints": [{"id":"v1","slot":"","text":"","status":"勾|叉|改","revisedText":"","reason":"","confidence":"","evidenceRefs":["F16"],"decisionFor":""}],
  "selectionNote": "",
  "materialsNote": "",
  "materials": [{"id":"F16","category":"","summary":"","source":"","tier":"","url":""}],
  "scraps": [{"text":"","whyUnused":"","source":""}],
  "gates": [{"name":"","violations":["…原文…"]}],
  "precheck": {"files":[{"name":"","raw":""}]},
  "preread": [{"voice":"","questions":[""],"sanfan":""}],
  "decisions": [""],
  "extractionNotes": [{"field":"","note":""}]
}
```

字段说明与取值规则：

- `meta.runId`：run 目录名（如 `2026-07-13-科技教研员`）。`meta.date`：目录名日期前缀。
- `meta.title`：最靠后交付版成稿的 H1 标题（优先级 `聚拢版_初稿可阅读.md` ＞ `初稿_可阅读.md` ＞ `成稿.md`）；三件全缺 → 留空，页面回退显示 runId，记 extractionNotes。
- `meta.panxing`：问题判型（v2 单：方向书/结构单判型栏原文）。v1 单无此栏 → 空串＋extractionNotes 记"v1 单无判型栏"。
- `meta.yongtu`：用途类型（方向书第四节勾选行原文，含"低置信度图纸"等标注）。**扩展字段**（任务书数据模型未列，方向书第四节的落点）。
- `meta.engine` / `meta.gouxuanlv`：台账 `ledger_row.md` 键值表对应单元格原文（勾选率原文若带"代理预演·非质量背书"字样须一并保留——红线 1）。台账缺失 → 空串＋extractionNotes。
- `direction.yiti`：方向书"## 一、议题"节正文原文（去标题）。`direction.jiantou`：倾向箭头节所有 `- [x]` 勾选行原文（去 checkbox 标记）。`direction.duzhe`：读者层级勾选行原文。`direction.jinqu`：禁区节各行原文（含"未设禁区"表态行；一行一条）。`direction.zhijue`：半成形直觉节正文原文；留白 → 空串（页面显示"留白"）。
- `sections[].id`：`s1…sN` 按成稿节序。`heading`：小标题行原文（含"一、"序号）。`mainlineSeg`：主线段标注（`表现|归因|建议|其他`）——v2 单取结构单"主线段-节问题链"；v1 单无 → 空串＋extractionNotes。`viewpointIds`：本节对应观点 id 列表（推断规则见 §三）。
- `viewpoints[].id`：`v1…vN` 按观点清单编号。`slot`：拟落槽位原文。`text`：判断句原文（粗体句）。`status`：勾/叉/改（来源见 §二·勾选记录）。`revisedText`：改后句原文（status=改 时必填）。`reason`：勾选记录"备注"列原文。`confidence`：置信度行原文（如"中（窗口期判断掺有预判）"）。`evidenceRefs`：证据摘要行全部 F 锚（按出现序，去重）。`decisionFor`：拍板对应行原文。
- `selectionNote`：**扩展字段**。勾选记录正文除勾选表外的附加说明原文（结构提案采用结论＋组稿附带约束＋签字句），页面观点区顶部整块照录。无勾选记录 → 空串。
- `materialsNote`：**扩展字段**。料包文件头"口径纪律"段原文（含溯源纪律行），页面料包区顶部照录。
- `materials[].id`：`F<n>`，n＝料包"带源事实清单"编号。`category`：所属类目节标题原文（如"类目七·反证·预警料"）。`summary`：要点句原文（编号后至来源括注前；条目内的 `[待核]`、`【反证】`、"打：…"等标注一律保留在 summary 内，不得删——红线 3）。`source`：`(...)` 括注来源原文。`tier`：T1/T2/待核；无则空串。`url`：第一条 URL 原文；多条取首条；无则空串。
- `scraps[]`：边角料箱编号条目。`text`：条目要点原文；`whyUnused`：条目中"正文未引用…可在XX中补充使用"一句原文（无此句 → 空串＋extractionNotes）；`source`：条目来源 URL 原文。
- `gates[].name`：闸门分节标题原文（如"闸一 · 溯源闸 —— 无来源事实清单"）。`violations`：该闸登记的违例/观察/缺口条目原文，逐条一字符串（含补锚闭环、复核结论等处置原文，照录）；清单为空 → 空数组，页面显示"本闸无违例"。
- `precheck.files[]`：预检单全文原文（含表头尾），一份一元素，`name` 为文件名。**多份并列**（任务书数据模型为单份 raw，此处按"可并列多份"扩展）。
- `preread[]`：预读提词单两组口吻考题，一组一元素：`voice`＝该组节标题原文（历史单含当时顾问称谓，照录，页脚声明兜底）；`questions`＝考题逐条原文；`sanfan`：三翻模拟节全文原文（只挂在与其同源的组上，另一组留空串）。
- `decisions[]`：需作者定夺清单编号条目原文，逐条一字符串（含条目标题与正文）。
- `extractionNotes[]`：`field`＝字段名或文件名，`note`＝"缺失|推断|文件名变体|解析降级"等说明。生成时逐项自报，不得省略。

## 三、sections ↔ viewpoints 联动推断规则（仅此处允许推断）

1. **首选**：`outputs/论证结构单.md` 归并表的"节-观点"映射（v2 单）。
2. **缺此件时**（v1 单）依次使用：
   a. 闸门报告"方向保真闸"两路回溯条目（`§N → 已勾观点M` 原文）；
   b. 观点清单"拟落槽位"与小标题文字的槽位对应（如小标题含"定调"对应拟落槽位=定调的观点）；
   c. 小标题与观点 slot/文本的文字相似度。
   推断联动**必须**在 extractionNotes 记一条（field=`sections[].viewpointIds`，note 写明推断依据 a/b/c）。
3. 一节对多观点如实并列；一观点不属任何节（如被叉）不出现在主线链，但观点区必须呈现。收束/结语类节无对应观点 → `viewpointIds: []`，页面标注"本节无对应观点"。

## 四、嵌入与转义规则

1. 生成器把 JSON 整体替入 `page_template.html` 中 `/*__RUN_DATA__*/` 占位符（该占位符位于 `const RUN_DATA = /*__RUN_DATA__*/;`）。
2. 替换前 `JSON.parse` 自检 JSON 合法；字符串内若出现 `</script>` 改写为 `<\/script>`（正常中文内容不会触发，属保险）。
3. 页面一切数据经 DOM `textContent` 注入，不拼 HTML——原文里的 `<`、`&` 等字符无需转义也不构成注入。
4. 来源 URL 一律纯文本呈现，不生成 `<a>` 超链（守"零外链、无网络请求"底线）。
5. 落盘 `<run>/outputs/回顾页.html`（UTF-8）。回顾页是 run 目录内唯一新增文件。

## 五、extractionNotes 常见条目（样例，按实填写）

- `{"field":"论证结构单.md","note":"缺失：v1 单无此件，sections[].viewpointIds 按方向保真闸回溯＋拟落槽位推断"}`
- `{"field":"meta.panxing","note":"缺失：v1 单无判型栏"}`
- `{"field":"sections[].mainlineSeg","note":"缺失：v1 单无主线段标注"}`
- `{"field":"料包.md","note":"文件名变体：实际为 outputs/料包.md（与候选名一致则无需此条）"}`
- `{"field":"scraps[2].whyUnused","note":"条目无'正文未引用'句，留空"}`
- `{"field":"outputs/观点清单与结构提案.md","note":"候选文件名第 2 顺位命中"}`

## 六、总览页轻量摘要字段（runs/回顾总览.html 专用·不做全量抽取）

> 总览页只对每个 run 抽下列摘要字段，**不得**为总览做 §一 全量抽取。总则三原则（候选名按序探测／容错不算错误／只读零编造）与转义规则（§四）全部沿用；占位符为 `overview_template.html` 的 `/*__OVERVIEW_DATA__*/`，落盘 `runs/回顾总览.html`。

```json
{
  "runs": [{
    "runId":"", "date":"", "title":"",
    "panxingLabel":"判型|用途类型", "panxing":"",
    "gouxuanlv":"", "engine":"",
    "deliverables":["初稿_可交付.docx"],
    "reviewPage":"<run-id>/outputs/回顾页.html 或 null",
    "runNotes":[""]
  }],
  "extractionNotes": [{"field":"","note":""}]
}
```

字段说明与取值规则：

- `runs[]`：扫描 `runs/` 下全部 run 目录（含只有方向书的容错单，一个不漏），按 run-id 倒序排列（新单在上）。
- `runId`／`date`：run 目录名／目录名日期前缀。
- `title`：同 §一 `meta.title` 规则（优先级 `outputs/聚拢版_初稿可阅读.md` ＞ `outputs/初稿_可阅读.md` ＞ `outputs/成稿.md` 的 H1；三件全缺 → 留空，页面回退显示 runId，记 extractionNotes）。
- `panxingLabel`／`panxing`：v2 单取方向书/结构单判型栏原文、label 填"判型"；v1 单取方向书第四节用途类型勾选行原文（含"低置信度图纸"等标注）、label 填"用途类型"。两栏皆缺 → 留空＋extractionNotes。
- `gouxuanlv`：台账 `ledger_row.md` 勾选率单元格原文；原文若带"代理预演·非质量背书"等字样须一并保留（红线 1）。台账缺失 → 空串＋extractionNotes。
- `engine`：台账执行引擎单元格原文；台账无此栏 → 空串＋extractionNotes。
- `deliverables[]`：只列**在场**交付件文件名，候选三件按序探测：`outputs/初稿_可交付.docx`／`outputs/聚拢版_初稿可阅读.md`／`outputs/成稿.md`；三件全缺 → 空数组。**只作"在场产物"事实清单，不得换算完成度、进度或百分比。**
- `reviewPage`：`outputs/回顾页.html` 在场 → 填相对路径 `<run-id>/outputs/回顾页.html`（卡片整卡链接用，包整体拎走后仍有效）；不在场 → `null`（页面标"回顾页：未生成"）。
- `runNotes[]`：该单级缺件/容错说明（如"容错单：仅方向书在盘"），并入 `extractionNotes` 呈现。
- `extractionNotes[]`：总览级＋各单级缺件/文件名变体说明，逐条自报，不得省略。

**总览专用纪律**：状态徽记只许"在场/缺件"事实陈述；禁止进度条、百分比完成度、红黄绿颜色分级评价（红黄绿＝评价，禁）。总览页不嵌生成时间戳——生成时间以文件修改时间为准，这也使重建幂等可字节级核对。

## 七、实时抽取器（File System Access API 直连模式·JS 端口真源）

> 2026-07-21 增补。总览页双模：默认渲染 `/*__OVERVIEW_DATA__*/` 内嵌静态快照（Safari/未授权兜底，§六 不变）；Chrome/Edge 下用户授权 `runs/` 目录后，页面内 JS 实时抽取器直连 run 文件夹现场抽取、覆盖渲染。本节是实时抽取器的字段映射真源，与 §六 同一数据模型；自检脚本 `skills/run-review/tests/live_extractor_test.mjs`。

1. **目录解析**：遍历用户所选目录句柄的子目录，名字匹配 `^\d{4}-\d{2}-\d{2}-` 者为一个 run，按名倒序。用户误选包根时自动下钻 `runs/` 子目录一次。
2. **文件访问经 io 接口注入**：抽取器签名 `liveExtractAll(io)`，`io = {listRuns(), readText(runId, rel), exists(runId, rel)}`——浏览器传 FS API 实现，node 自检传 fs 实现。抽取器本身不含 DOM/浏览器 API，包裹在模板 `/*__LIVE_EXTRACTOR_START__*/…/*__LIVE_EXTRACTOR_END__*/` 标记内供测试抽出。
3. **逐字段映射**（候选文件名与 §六 一致）：
   - `title`：三件交付版按序读 H1（同 §六）；缺失回退 runId＋runNotes。
   - `deliverables`／`reviewPage`：`exists` 探测，规则同 §六。
   - `panxing`／`gouxuanlv`／`engine`：**首选台账 `ledger_row.md`**，兼容两种表形——行式表（表头含 `run_id`，按列表头"判型/切法/用途类型/勾选率|确认率|采纳率/执行引擎"对位取下一数据行单元格）与键值表（表头 `| 字段 | 值 |`，逐行按首格键名对位）。单元格清洗：去 `**`/反引号、`<br>`→"；"、压缩空白。切法列独立存在时取"切法X"并入判型（`（切法X）`）。
   - **代理预演标注**：勾选率单元格未含"代理预演"而台账全文含代理预演声明时，追加"（代理预演·非质量背书）"（红线 1 的机械兑现）。
   - **方向书兜底**：台账无判型/用途类型栏时读 `方向书.md` 第四节（`## 四、问题判型`→label 判型；`## 四、用途类型`→label 用途类型），取第一个 `- [x]` 行，去 `——` 后说明、去 `[AGENT-WRITER…]` 标注；节内含"低置信度图纸"字样则一并带上。
4. **容错沿用总则三原则**：任何文件读取/解析失败不中止——字段留空、记 runNotes（并入 extractionNotes 页面可见）。
