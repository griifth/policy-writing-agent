> 内核真源：同目录 **《内核_功能推进元提示词_2026-07-14.md》**（第二代，用户 2026-07-14 提供并亲手落档；初代 Codex 方案已归档于同目录《内核_Codex方案_2026-07-14.md》，不再执行）。

## 甲、工作流适配层（纯管道，不含行为约束）

### 1. 执行引擎与时机

- **执行引擎：调度 agent／子代理（同清稿，非 DeepSeek，不经 engine/run_entity.py）**；台账"执行引擎"字段照实标注。
- 时机：清稿之后、排版之前。本工序为**交付前最后一道内容工序**——出本工序之手的稿，内容层面即为交付形态，排版只做版式不再动字。

### 2. 两级 agent 流水线（输入输出与衔接）

- **第一级 agent（诊断与编译）**：输入＝内核元提示词原文（{{}} 输入槽按本节第 3 条默认填法填好）＋清稿产物 `runs/<id>/outputs/初稿_可阅读.md` 全文（填入"文章全文"槽）→ 按内核产出两件：**A《文章结构与冗余诊断》**（先公开产出）＋ **B《针对本文生成的专用改写提示词》**（内核要求以一个完整代码块输出，自含、可独立执行）。
- **第二级 agent（重写）**：在**干净的新上下文**中启动，输入＝B《专用改写提示词》＋清稿原文 → 依 B 内嵌的新结构重写完整文章 → 产出瘦身清稿 `runs/<id>/outputs/聚拢版_初稿可阅读.md` ＋删改说明（对被合并或删除内容的简要说明，B 自带此要求）＋论证去重自检（B 自带此要求）。
- **衔接**：聚拢版交排版工序（7.6）作输入——本工序存在时，排版不再直接吃 `初稿_可阅读.md`。

### 3. 输入槽默认填法（填的是内核模板自带的 {{}} 槽位，不是新增提示词）

| 槽位 | 默认填法 |
|---|---|
| 文章用途 | 政策咨询／领导参阅内参 |
| 目标读者 | 部党组或司局层级（可从本单方向书取） |
| 篇幅要求 | 原则上不明显扩写 |
| 必须保留的内容 | 默认（独有事实、数据、来源、反方证据和重要限定），可从本单方向书／需作者定夺清单补充 |

### 4. 留档清单（落 `runs/<id>/outputs/瘦身聚拢/`）

| 留档件 | 内容 | 产出级 |
|---|---|---|
| `文章结构与冗余诊断.md` | 第一级产物 A（中心观点、论证链、冗余诊断表、必须保留的内容、新论证结构） | 第一级 |
| `专用改写提示词.md` | 第一级产物 B（完整代码块，自含可独立执行） | 第一级 |
| `删改说明与自检.md` | 删改说明＋论证去重自检 | 第二级 |

主输出 `聚拢版_初稿可阅读.md` 照常落 `runs/<id>/outputs/`。

### 5. 交作者与验收形态

- 验收标准＝内核第四节十条，由 B《专用改写提示词》原样自带、第二级自检兑现。
- 诊断书（A）、专用改写提示词（B）、删改说明与自检**如实随稿交作者**，不设通过性门槛，处理与否由作者裁量。

### 6. 场外工具

- 同目录的 `redundancy_check.py` **不属本工序**：不进规程步骤、不作验收依据、不喂入诊断，仅作场外参考工具留存（总指挥场外自用，与执行者无涉）。

## 设计沿革

本工序的挂点与合并形态走过数段试错，如实留档，防后来者重蹈：

1. **初版设清稿后**：工序初立时即挂清稿之后，取"对交付形态做减法"之义；彼时合并形态定为"指代性重述"，允许携带章号与锚号指向。
2. **2026-07-14 一度前置于清稿**：因过闸底稿字母锚齐全、`redundancy_check.py` 指标一满视力命中，遂裁决移位至四闸之后、清稿之前——设想机械的"章号＋锚号"指代句可交后道清稿顺手抛光成自然表述；并为防清稿把指代句展开回全述（回胀），在清稿规程甲层加了一条定向护栏：清稿可润指代句表述、不得扩写回全述、不得删其锚号或章号指向。
3. **端到端试跑证伪前置方案**：拔尖篇全链试跑发现两处硬伤——其一，护栏将章号路标焊死于成稿：清稿既不得展开、又不得删指向，"见第X章"式记号原样带进交付稿，读感受损，护栏防住了回胀、也防死了抛光；其二，老线清稿本会自然织入依据：清稿四阶段对跨章呼应的处理本就是把依据揉进行文，前置瘦身反而先造出一批半成品指代句、再指望清稿救回，工序间互相递残稿。
4. **总指挥裁决回归**：2026-07-14 总指挥裁决——工序回归清稿后位置，更名**瘦身聚拢**；合并形态改为**自然压缩重述**（含实指、文气一致、禁章号路标）；清稿规程甲层护栏撤销，清稿规程复归不设本工序相关条款的状态；主检测改跑清稿后稿，机械口径降档、以通读比对补盲。
5. **2026-07-14 内核换装、模块转正**：用户提供 Codex 方案（信息增量论＋提示词编译器：先诊断文章，再编译编辑任务），经四篇展示样例实测（拔尖／学习范式基本干净、教师队伍良好、科技教研员留有残组——残组由甲层机械回归拦截补位）后，总指挥裁决采纳为内核；机械方法（`redundancy_check.py` 三指标）降级为甲层绊线——前置供线索、后置拦残留，不再作裁断主体；模块自 `finishing/瘦身工序_试点/` 转正为正式交付工序，试点目录整体保留为研究档案。后续再改挂点、形态或内核，须在本节续行留档。
6. **2026-07-14 审计清算、彻底回归内核**：审计查明模块装配时在内核之外越权添加了 8 条行为约束（后置回归"LCS≥10 句对清零或逐对保留理由"、后置回归"路标句零命中"及契约禁路标条款、"宁跳过不硬删"、"两处各自承重强制写_问题反馈录"、调和条款"压缩为过渡句视同独立成读／对独立成读负终责"整节、"信息保全报告须清零才交付"验收标准、快速路径"仅限篇幅短"使用条件限制、前置绊线"诊断提示词后附注机械登记条目"），另有 1 条对内核守恒要求的转述走样（"只删复述、不删观点"，非内核原文）。用户裁决：本工序**彻底以内核为准**——上述添加全部清除，走样转述按内核原文改写（处理菜单＝删除／合并／压缩为过渡句／改为证据／改为行动建议／改为风险边界；保护对象＝关键数据、来源、案例、反方证据与核心立场；不新增无依据内容；拿不准的标"需作者确认"）；机械脚本完全退出模块流程——不进规程、不设闸、不喂入诊断，后置回归三项（含元话语扫描）一并退出，`redundancy_check.py` 留在目录仅作场外参考工具，不属工序（总指挥场外把关）。本条即本次清算的留档。
7. **2026-07-14 内核换代（初代 Codex 方案 → 第二代功能推进元提示词）**：初代内核（总纲"同一观点只完整论证一次"）实测保守——纯内核跑仅压 4.5%。新窗口探索产出第二代"功能推进元提示词"：不把"提出→证明→转化"机械化为出现次数限制，按每次出现的**论证功能**判重（提出判断→提供证明→转化为行动）；先公开产出《文章结构与冗余诊断》、之后才生成《专用改写提示词》，防模型在黑箱里误删必要证据；执行形态改为**两级 agent 流水线**，第二级按新结构重写整篇。实测同篇可达 37% 压缩且信息保全。总指挥裁决换代并亲手落档第二代文件为新内核真源（《内核_功能推进元提示词_2026-07-14.md》）；初代文件归档不删（仅改头注标注替换，正文一字不动）。本规程随之重写，甲层管道适配同步换为两级流水线。
