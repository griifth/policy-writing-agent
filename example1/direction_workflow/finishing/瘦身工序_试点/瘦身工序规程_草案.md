# 瘦身聚拢工序规程（草案 · 交付工序体外试点：合规性复述 → 自然压缩重述）

> 路径约定：本文件内相对路径一律以 direction_workflow/ 为根。
> 所属：direction_workflow · 交付工序（体外试点）。挂点：清稿（`finishing/清稿规程.md`）之后、排版（`finishing/排版规程.md`）之前（2026-07-14 总指挥裁决定位，沿革见§八）。全链定位：**组稿→四闸→底稿(成稿.md)→清稿→【瘦身聚拢】→排版**。
> **体外声明**：本工序为试点，不动三张图纸（元框架／元模块契约／调度宪法）、不动四闸（`gates/闸门规程.md` 与 `gates/precheck.py`）、不改清稿规程一字。试点期全部产物与脚本放 `finishing/瘦身工序_试点/`；未经转正，不得写入任何既有规程与图纸。
> 铁律：瘦身聚拢删的不是废话，是**合规性复述**。工作流为防松散设了回扣／反证／证据本地化等向心机制，闸门把「围绕主线」操作化成了「文本复现」，于是核心判断全文出现四到六次、同一证据在多章被完整引用并重复解释、建议章逐条复述前文、反证段「接住它」复述本章论点。本工序做的替换只有一种：**首述处全述承重，后续聚拢为自然压缩重述**——向心力一分不减，复现的字数减下来。
> 措辞纪律：与闸门规程同款——机械段只登记、不裁断；合并与保留是乙段（agent）与丙段（复核）的事，且每一处都留痕可查。

## 一、工序定位

### （一）工序位置：清稿之后、排版之前（终段瘦身聚拢板块）

本工序位于 **组稿→四闸→底稿(成稿.md)→清稿→【瘦身聚拢】→排版** 链条终段，吃清稿后可阅读稿、吐聚拢稿交排版，是**交付前最后一道内容工序**——出本工序之手的稿，内容层面即为交付形态，排版只做版式不再动字。

**瘦身聚拢必须在四闸与清稿之后**：承重闸校验的是全述形态的证据承重，会把压缩句判为装饰句，故不得置于四闸之前；清稿的锚还原、术语白话、句式去复读会改变全稿字面，故聚拢须在清稿定稿之后进行，一次做完、不再返工。此为硬顺序，不得倒置。

### （二）吃什么、吐什么、不管什么；检测时点

- **吃什么**：清稿后可阅读稿（`runs/<id>/outputs/初稿_可阅读.md`，清稿四阶段已完成，字母锚已还原为自然引述）。**主检测时点即清稿后稿**——直接对交付形态检测，测的就是读者将要读到的重复。
- **吐什么**：①《冗余登记表》（脚本产物＋通读比对补录）；②聚拢稿（交排版工序作输入）；③《瘦身说明》（逐条改动留痕）。正式接入后落 `runs/<id>/outputs/瘦身聚拢/`；试点期落本目录。
- **不管什么**：不管观点对错（方向保真闸的事）、不管来源真伪（溯源闸的事）、不管语域（precheck 的事）、不管 AI 痕迹与术语白话（清稿的事）。只管同一内容被全述了几遍、能不能聚拢成一句自然压缩重述。

### （三）检测口径：机械降档＋通读补盲

清稿后稿的字母锚（C1/E5/S2 类、「缺口N」式）已还原为自然引述，`redundancy_check.py` 的指标一（锚重复）只剩「作者＋年份」括注等兜底锚形可抓，**命中面窄一档，约一半指标盲区属预期**，脚本读数自始按降档口径看待，登记表头须注明「清稿后·降档口径」。

降档之盲由人补：**执行者（乙段前置动作）须对全稿做一遍通读比对**，将脚本漏检的同源证据复述、跨章同构解释补录入登记表（补录条目标「通读补录」），与脚本条目同等走后续流程。通读比对时**可调用 run 档案 `outputs/附件_来源锚*.md`（锚号↔出处对照表）辅助定位同源证据**——同一出处在正文的多处落点，正是脚本降档后最容易漏的那类条目。

## 二、三段式流程

### 甲段 · 机械检测（脚本出登记表，降档口径）

执行件：本目录 `redundancy_check.py`（纯正则／统计，不调用模型，风格同 `gates/precheck.py`）。

```
python3 finishing/瘦身工序_试点/redundancy_check.py <清稿后稿路径> > <冗余登记表输出路径>
```

三项指标（口径与可调参数写死在脚本头注，改线必须在脚本「调参记录」补一行，不许静默改）：

1. **锚重复**：同一来源锚（自然引述括注「作者＋年份」为主口径，残存字母锚、「缺口N」式、「料包」引用一并抓）跨 ≥2 章出现，且 >30 字解释性落点 ≥2 处 → 该锚全部落点逐条登记（位置＋原句＋句长）。**本指标在清稿后稿上为降档口径，漏检属预期，以通读比对补录为补**（见§一（三））。
2. **近逐字重复**：跨章句对（。！？切句，忽略 <15 字短句），字符 6-gram Jaccard ≥0.5 **或**最长公共子串 ≥10 字 → 登记一对（两句原文＋所在章＋判据）。
3. **高频判断短语**：(a) 书名号／引号包裹短语跨 ≥2 章；(b) 4–20 字重复子串跨 ≥3 章、全文 ≥4 次（最长化去包含、滤首末虚词串）→ 登记短语＋回数＋章分布。

登记表含汇总统计（各指标条数、估算冗余字数——粗估口径，三指标间有重叠，不可当删减额）。**登记表只登记、不裁断**；条目多不等于稿差，条目为零也不等于稿好——清稿后稿上条目偏少更是常态，不得因此免做通读比对。

### 乙段 · 合并执行（agent 按登记表操作）

执行引擎：调度 agent／子代理（同清稿，不经 engine/run_entity.py）。先完成通读比对补录（§一（三）），再逐条走登记表：

- 每条登记项，按下节「合并操作规则」处理，或写明**保留理由**（保留理由须落回登记表该条之下，如「机构名，非复述」「两处各自承重，见方向书第X栏」「无法自然完成合并，跳过」）；
- 处理顺序建议：指标一（锚重复，含通读补录条目）→ 指标二（句对）→ 指标三（短语），前项合并常顺带消掉后项条目；
- 全程受§四五条保护规则约束，任何一条与保护规则冲突时，**保护规则赢**，该条目走保留理由。

### 丙段 · 校验（独立复核）

由未执行乙段的一方（另开子代理或人工）做三件事，产出一页《校验记录》：

1. **登记表清零核对**：逐条看是否「已合并」或「有保留理由」，两者皆无的打回乙段；
2. **脚本复跑**：对聚拢稿复跑 `redundancy_check.py`（同为清稿后降档口径，前后可比），**以估算冗余字数下降为准绳**；三指标条数只作参考——降档口径下条数本就半盲，条数不降不据此打回（2026-07-14 验收裁决口径修缮）。未降项如实记录、交人裁量，**不许为压读数硬删内容**（与清稿规程守恒约束同款纪律）；
3. **主线完整性检查**：逐个小标题核对——标题判断句仍可回溯到已勾观点清单（口径同 `gates/闸门规程.md` 方向保真闸，此处只查聚拢是否弄丢，不重开闸）；建议章逐条核对——每条建议不回翻前文即可读懂（见§五调和条款）；读感抽查——随机抽三处合并句，验其是否为与上下文文气一致的常句、有无章号路标残留（§三.2 形态红线）。

## 三、合并操作规则

每条登记项的标准动作：

1. **选定保留位**：在该项的全部落点中，保留**承重最好的一处全述**——通常为首述处（首次给出证据＋解释的位置）；若首述处是短引、后文某处才是真正的全述＋解释，则保留后者，并在《瘦身说明》记明选位理由。若**两处各自承重、难分主从**，执行者**不得径行合并**，强制写 `_问题反馈录.md` 交裁量（见§七，2026-07-14 验收裁决口径修缮）。
2. **合并形态规格（2026-07-14 读感裁决，核心条款）**：其余落点一律聚拢为**自然压缩重述**——**≤30 字、含实指内容、与清稿文气一致的常句**，读者顺读而过不觉其为「引用」（如「加速的收益终有边界，实测增益止步 0.09」）。**禁用「如第X章所述」「（第一章已述）」「第X章已明」式章号路标与括注交叉引用**——章号路标与括注是给校对看的记号，不是给读者看的行文，一处不得出现在聚拢稿。**无法自然完成的合并跳过并记录**（登记表该条写「无法自然完成合并，跳过」＋一句原因），不硬删、不硬造压缩句。
3. **事实锚点随句走**：被压缩处原句携带的事实锚点（法名、年份、数字、分数线、出处引述），一个不丢——要么随压缩句保留，要么并入保留位的全述句（见保护规则②）。
4. **逐条留痕**：每处改动写入《瘦身说明》，格式固定三栏——**原文（全句照录）→ 改后（全句照录）→ 理由（登记表条目号＋选位依据）**。
5. 指标三（高频短语）类条目的动作是**换写不删意**：同一判断短语的第 N 次出现改为压缩重述或同义变述；专名（计划名、法律名、机构名）通常走保留理由，不强改。

## 四、五条保护规则（乙段的不可逾越线）

1. **首述处及其解释一律不动**——首次全述是承重位，动了它，后续所有压缩重述都悬空；
2. **事实锚点一个不丢**——法名、年份、数字、分数线等事实锚点，合并前后全稿集合必须完全一致；丙段可借 `outputs/附件_来源锚*.md` 对照表机械核对；
3. **建议章每条自足**——领导只翻建议章是常态阅读方式，建议条款不许压成需回翻前文方可读懂的残句，每条须留一句读得懂的实指压缩重述；
4. **只删复述、不删观点、不改判断**——已勾观点一行不减，判断措辞力度不升不降（力度改动是清稿「需作者定夺」的地界，不是瘦身聚拢的）；
5. **每处改动逐条写入《瘦身说明》**（原文→改后→理由），不许打包描述「本章若干处压缩」；静默处理即违例。

## 五、与清稿「各章独立成读」的调和条款

清稿内核阶段二规定：简称指代在结论处须写出实指内容，「各章应可独立成读，不依赖跨章交叉引用」。聚拢发生在清稿之后、属交付前最后内容工序，调和口径如下：

- **「一句自然压缩重述」视同独立成读**：一章内对他章证据的呼应，只要留有一句 ≤30 字、含实指内容、文气自然的压缩重述（§三.2 形态），即满足独立成读要求。此为**本工序自身验收口径**（丙段主线完整性检查项之一），由本工序自查自验，不依赖清稿侧任何条款兜底；
- 聚拢稿出手即交付形态，**本工序对独立成读负终责**：清稿已兑现的独立成读，聚拢不得破坏——凡合并使某章非回翻他章不可读的，即违反§三.2 形态规格，该条打回或走「跳过并记录」；
- 个案冲突时（如某处非全述不可读、压缩即失义），停止拉锯，把该处写进 `_问题反馈录.md` 交人裁量，不许硬压、不许静默保留而不留痕。

## 六、验收标准

四项全满足方可交排版：

1. **登记表清零**：《冗余登记表》（含通读补录条目）每条目「已合并」「有保留理由」或「无法自然完成合并，跳过」三态之一，无悬空条目；
2. **读数下降**：聚拢稿复跑 `redundancy_check.py`（清稿后降档口径），**以「估算冗余字数下降」为准绳**，不以落点条数为准绳——降档口径下条数半盲属口径特性，条数持平不判不合格（2026-07-14 验收裁决口径修缮；未降项须有丙段记录的人工裁量结论）；
3. **主线完整、读感无损**：小标题判断句仍可逐条回溯已勾观点清单；建议章每条自足可读（保护规则③兑现）；丙段读感抽查无章号路标、无括注交叉引用残留；
4. **留痕齐全**：《瘦身说明》逐条三栏齐全，事实锚点集合前后一致核对通过。

## 七、遇规程未覆盖时

本规程只管「全述→自然压缩重述」这一种替换。若某篇出现口径无法机械判定的情形（如压缩后语义有歧），**停止猜测**，写进 `_问题反馈录.md`，不自行加判据、不静默绕过（同 `gates/闸门规程.md` §六纪律）。

其中「**两处全述各自承重、难分主从**」情形为**强制反馈项**（2026-07-14 验收裁决口径修缮）：执行者不得径行合并、不得自选保留位，必须原样写进 `_问题反馈录.md`（两处原文＋各自承重点）交裁量，裁量结论回填后方可动稿。

## 八、设计沿革

本工序的挂点与合并形态走过三段试错，如实留档，防后来者重蹈：

1. **初版设清稿后**：工序初立时即挂清稿之后，取「对交付形态做减法」之义；彼时合并形态定为「指代性重述」，允许携带章号与锚号指向。
2. **2026-07-14 一度前置于清稿**：因过闸底稿字母锚齐全、`redundancy_check.py` 指标一满视力命中，遂裁决移位至四闸之后、清稿之前——设想机械的「章号＋锚号」指代句可交后道清稿顺手抛光成自然表述，两道工序各司其职；并为防清稿把指代句展开回全述（回胀），在清稿规程**甲层**加了一条定向护栏（原甲.6）：清稿可润指代句表述、不得扩写回全述、不得删其锚号或章号指向。
3. **端到端试跑证伪前置方案**：拔尖篇全链试跑发现两处硬伤——其一，**护栏将章号路标焊死于成稿**：清稿既不得展开、又不得删指向，「见第X章」式记号原样带进交付稿，读感受损，护栏防住了回胀、也防死了抛光；其二，**老线清稿本会自然织入依据**：清稿四阶段对跨章呼应的处理本就是把依据揉进行文，前置瘦身反而先造出一批半成品指代句、再指望清稿救回，工序间互相递残稿。
4. **总指挥裁决回归**：2026-07-14 总指挥裁决——工序回归清稿后位置、定位为终段「瘦身聚拢板块」；更名**瘦身聚拢**；合并形态改为**自然压缩重述**（≤30 字、含实指、文气一致、禁章号路标，见§三.2）；清稿规程甲层护栏**撤销**，清稿规程复归不设本工序相关条款的状态；主检测改跑清稿后稿，机械口径降档、以通读比对补盲（见§一（三））。本节所记为裁决之全部，后续再改挂点或形态，须在本节续行留档。
