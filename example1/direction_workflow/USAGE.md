# direction_workflow 使用指南（装配式政策报告工作流）

> 读者：撰写者本人，或替撰写者跑流程的操作员。不需要了解本系统的任何设计史。
> 一句话：**你出方向和判断（合计约 90 秒），机器出材料、结构和草稿，你从草稿里搬零件进自己签名的报告。**

---

## 〇、流程从哪里开始，到哪里结束

- **起点**：你手里有一个题——可以是模糊的（"想写终身教育方面的"），也可以是明确的（"十五五教师AI素养培训布局"）。对装配工说一句 **「接单：〈你的主题〉」**，流程即开始。
- **终点**：机器把可交付初稿连同备查件交到你手上——**初稿_可交付.docx（主件）＋初稿_可阅读.md＋底稿与附件（备查）＋需作者定夺清单**——你确认收货、台账记完，流程即结束。
- **系统边界（重要）**：本系统的终点在"交给你"为止。**改写、署名、报送是你的事**——系统不打分、不判稿件优劣、不替你决定报不报；判断和责任始终在人。报送前，稿里的关键数字须人工抽验（系统保证每个事实带来源锚，但"锚在"≠"锚对"）。

## 一、开跑前的环境（一次性）

1. 在装有本包 skills 的 Claude Code / agent 会话中操作（新机器部署见 `移植说明.md`）。
2. 需要联网（侦察与检索是真网搜）。
3. 生产单需 DeepSeek 密钥（沿用仓内既有 `.env`；配置说明见 `engine/README.md`）。试跑单可 agent 直写，但台账须标注执行引擎。

## 二、全流程一图（★＝你出手的地方）

```
「接单：主题」
   ↓
① 侦察（机器，分钟级）→ 态势速览一页纸（最近谁动了什么/分歧轴/反直觉信号/候选问题）
   ↓
② ★触点一·定方向（你，约1分钟）：对着速览点选，签《方向书》六栏——
   议题｜倾向箭头（你站分歧轴哪端）｜读者层级｜用途类型（借鉴/研判/追赶）｜禁区｜（选填）半成形直觉
   每栏都有逃生口"以上都不是，我关心的是____"——机器猜偏了就填它
   ↓
③ 结构单（机器）：按你的用途类型从元框架取变奏，定本篇槽位与详略
④ 全量检索（机器，真联网）：按方向书加权（箭头定方向、禁区剪枝），出带来源料包
⑤ 立论（DeepSeek）：产出《观点清单》约10行——每行一个可反驳的判断＋证据摘要＋给谁拍板
   ↓
⑥ ★触点二·认观点（你，约30秒）：逐行 勾／叉／改
   ——勾了的进稿，叉了的死，改了的按你的来。勾选率低于一半＝方向没拿准，自动回②重来
   ↓
⑦ 组稿（DeepSeek 落笔）：小标题＝你勾过的观点句；段首可引用主张；段身条款级证据带来源；
   每章反证栏（打观点的材料如实摆出）；文末边角料箱（没用上的好料）
⑧ 四闸（机器，只出违例清单不打分）：溯源闸/承重闸/方向保真闸/语域预检 → 违例自动返修
⑨ 预读提词（机器调两位所长思维模型）：一张"考题预告"——
   "这条建议谁牵头？层级够吗？""跟纲要哪节挂接？""题目三秒立得住吗？"＋三翻模拟
   ↓
⑨.5 清稿（agent 执行，非 DeepSeek）：按 finishing/清稿规程.md 去 AI 痕迹、判断清晰化、术语白话化
    → 初稿·可阅读＋改动说明＋需作者定夺清单；边角料箱与来源锚移出正文成附件
⑨.6 排版（agent 跑脚本）：按 finishing/排版规程.md 导出 初稿·可交付 docx（内参版式，三项自检）
   ↓
⑩ ★收货（你）：初稿可交付 docx（主件）＋初稿可阅读＋底稿＋附件（边角料箱/来源锚/提词单）＋定夺清单。
   定夺清单逐条裁量，搬你要的句子进自己的报告，按提词单预答领导的问题
   ↓
台账回填：勾选率（自动）｜采用句数（你数几句进了终稿）｜复购（下次你还来不来）——流程结束
```

## 三、你的 90 秒怎么花（两个触点详解）

**触点一（约 1 分钟）**：不要凭空想"我的观点是什么"——看速览。分歧轴两端就是现成的立场选项，"你站哪端"一秒可答；候选问题挑一个或改一个；禁区想 20 秒（什么不能碰）；有半成形的直觉就写一句，没有不填。
**触点二（约 30 秒）**：清单上每行是一个完整判断句。凭直觉勾——这话你敢放进自己署名的报告就勾；不敢就叉；意思对但话不对就改。**改过的句子会一字不差成为小标题。**

## 四、你收到的东西怎么用

| 交付物 | 定位 | 用法 |
|---|---|---|
| **初稿_可交付.docx** | **主件** | 内参版式、已清 AI 痕迹的可阅版，可直接过手署名；对照"需作者定夺清单"逐条裁量后即可走报送 |
| **初稿_可阅读.md** | 主件的 md 原文 | 想改文字从这份改，改完按排版规程重出 docx |
| **需作者定夺清单** | 必看 | 清稿替你往前推了一步的所有位置（措辞加重/内容删除/技术条款去留），逐条拍板，不看等于默许 |
| **底稿（成稿.md）** | 备查 | 清稿前的原始过闸稿，带全部来源锚与反证栏；核验与回捞素材用 |
| **附件_边角料箱** | 备查 | 正文没用上的好料，每条注明为什么没用——写自己的稿时最值得翻 |
| **附件_来源锚** | 备查 | 全文来源清单（清稿时移出正文），报送前抽验关键数字顺着它回源 |
| **预读提词单** | 备查 | 你老板可能会问的问题预告。报送前把每个考题自己先答一遍 |

## 五、这个系统不做什么（边界声明）

- **不打分、不评档、不判断你的稿好不好**——历史上三代评分标尺已证明 AI 判不了"值得报送"，判定权在人。
- **不替你立场**——观点清单是候选，勾选权在你；机器夹带方向书之外的私货会被方向保真闸打回。
- **不保证事实无误**——保证可溯源（每个事实带锚），报送级核验仍需人工抽查。
- **不代报送**——终点是交付给你。

## 六、目录地图（一单跑完后去哪找东西）

```
runs/<日期-主题>/
├─ 方向书.md / 结构单.md          ← 你的合同与本篇图纸
├─ generated/                     ← 本篇现场制造的实体提示词（可复盘"机器当时被要求干什么"）
├─ outputs/                       ← 态势速览、料包、观点清单、成稿（底稿）、初稿_可阅读、初稿_可交付.docx、
│                                    改动说明、需作者定夺清单、附件_边角料箱、附件_来源锚
├─ gates/                         ← 预检单与三闸违例清单
└─ ledger_row.md                  ← 台账行（含执行引擎标注）
```

## 七、维护纪律（改东西的人必读）

1. **图纸真源在 `records/`**（元框架/契约/宪法），包内 `blueprints/` 只是快照——改设计先改真源，再重新快照，勿只改副本。
2. **skill 双份**：`~/.claude/skills/` 是运行实例，包内 `skills/` 是移植母本——升级内核两处同步，只改一处必分叉。
3. 词表（`gates/register_blacklist.md`）与纲要地图（`skills/cao-thinking/references/纲要地图.md`）随政策周期滚动更新，来源日期必须标注。
4. 两位所长思维模型现为"论文+会议"蒸馏 V2；拿到审改痕迹语料后重蒸，接口不变。
