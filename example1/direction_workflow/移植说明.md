# direction_workflow 移植说明

> 本包定位：可整体拎走的自包含包。除本文「外部依赖」节所列项外，运行所需的图纸、模板、skill、闸门与词表全部随包携带。
> 编写日期：2026-07-13。

---

## 一、整包拎走怎么用（相对路径约定）

1. **整目录复制** `direction_workflow/` 到任意位置（新机、新仓库均可），内部结构不动。
2. **路径约定**：包内 skills/、templates/、gates/ 的规程文件顶部均有一行「路径约定：本文件内相对路径一律以 direction_workflow/ 为根」。即：
   - `templates/方向书模板.md` ＝ `<你放置的位置>/direction_workflow/templates/方向书模板.md`
   - `skills/report-clarify-v2/SKILL.md`、`blueprints/元框架.md`、`gates/register_blacklist.md` 同理。
   - 读这些文件的 agent，工作根应取 direction_workflow/ 目录本身。
3. **Python 依赖**：`pip install -r requirements.txt`（python-docx＝排版工序；openai＝DeepSeek 生产单；precheck 纯标准库）。运行依赖全貌见 `依赖说明.md`；Windows 平台差异见文末「五、Windows 附注」。
4. **机械闸自检**：`gates/precheck.py` 读取与其同目录的词表快照 `gates/register_blacklist.md`，随包即用：
   ```bash
   python3 gates/precheck.py <某篇成稿.md>
   ```
5. **两个锚点变量**（个别文件用到，均在文件头定义）：
   - `<ROOT>` / `<REPO>` ＝ direction_workflow/ 的**上一级目录**（原仓库根）。只在涉及包外资源（旧引擎、历史沙箱）时出现；纯包内流程用不到它。
6. `runs/` 历史单与 `_skill_snapshots/` 是历史留痕，**不作运行依赖、不改写**；发布包（GitHub main）不携带历史单与快照，完整留痕在内部仓库分支。

## 二、三个 skill 在新机的安装法

包内 `skills/policy-report-assembler/`、`skills/topic-ideation/`、`skills/strategy-preread/` 是完整副本（含 references/、agents/）。要在新机按名触发，复制到新机的 `~/.claude/skills/`：

```bash
cp -R direction_workflow/skills/policy-report-assembler ~/.claude/skills/
cp -R direction_workflow/skills/topic-ideation          ~/.claude/skills/
cp -R direction_workflow/skills/strategy-preread        ~/.claude/skills/
```

**必须注意：装进 `~/.claude/skills/` 后，相对路径锚点会失效。** 包内 SKILL.md 的相对路径（`blueprints/…`、`templates/…`、`skills/…`）以 direction_workflow/ 为根；skill 被装到 `~/.claude/skills/` 之后，运行时不再有这个根，`blueprints/元框架.md` 这类路径将无从解析。安装后须把安装件里的相对路径替换为新机上 direction_workflow/ 的绝对路径。sed 示例（假设新机整包放在 `/home/you/direction_workflow`）：

```bash
DW="/home/you/direction_workflow"   # 改成新机实际放置路径
sed -i '' \
  -e "s|\`blueprints/|\`${DW}/blueprints/|g" \
  -e "s|\`templates/|\`${DW}/templates/|g" \
  -e "s|\`skills/|\`${DW}/skills/|g" \
  ~/.claude/skills/policy-report-assembler/SKILL.md
```

（Linux 的 GNU sed 去掉 `-i` 后面的 `''`。topic-ideation 与 strategy-preread 的 SKILL.md 只用 skill 目录内 `references/…` 相对路径，随目录整体复制即自洽，通常无需替换；policy-report-assembler 是引用包内图纸/模板最多的一个，必须替换。）

只作路径读取调用（不装进 `~/.claude/skills/`、由调度 agent 直接读包内 SKILL.md 执行）则**无需任何替换**——这正是包内 report-clarify-v2 / topic-material-search-v2 的既定用法。

以下随包文件是**快照**，不是真源。修改设计请改真源并重新快照（复制过来并保留文件顶部的〔快照〕头注、更新日期），勿只改包内副本：

| 包内快照 | 真源（原仓库内） |
|---|---|
| `blueprints/元框架.md` | `example1/records/元框架提炼_2026-07-12/元框架.md` |
| `blueprints/元框架v2_问题主线.md` | `example1/records/主线架构迭代_2026-07-15/元框架v2_问题主线.md` |

同样，`skills/` 下三个顾问/装配 skill 与本机 `~/.claude/skills/` 安装件互为副本：内核改动应两处同步（或改一处后重新复制），本机安装件的绝对路径版本不要回灌进包。

## 四、外部依赖清单

以下资源在包外，**不随包携带**；缺它们时对应功能受限，其余流程不受影响：

1. **旧引擎 `strategic_response_workflow/`**（原仓库根下）——topic-material-search-v2 **全量模式**的 DeepSeek 复审（`workflow/llm_client`，含 `.env` 内 API key）与写作工作流 hand-off（`workflow/runner.py`、`report_modules/`）依赖它。涉及文件：`skills/topic-material-search-v2/references/environment.md`、`references/review-standard.md`（内以 `<REPO>` 锚点引用）。新机无此引擎时：侦察模式（scout mode）与检索、组稿、四闸全部照常；仅 DS 复审循环与 runner.py hand-off 不可用。
2. **历史沙箱 `712测试/`**（原仓库根下）——report-clarify-v2 / topic-material-search-v2 文件头的「沙箱版」说明所指，仅原机存在，属研发期留痕；真实使用落盘 `runs/<run-id>/`，移植后无需此目录。
3. **会议原始转写与证据摘录**（内部仓库）——两个顾问 skill 的蒸馏溯源材料（会议证据/蒸馏报告）自 2026-07-20 起**不随包分发**，存于内部仓库；日常运行不依赖（skill 正文已移除相应引用）。
4. **蒸馏过程材料**（内部仓库 records/ 与旧引擎 runs/）——两个顾问 skill 蒸馏时的过程留痕，性质同上，运行不依赖。
5. **报送导出脚本真源 `scripts/neican_docx.py`**（内部仓库）——已快照入包为 `tools/neican_docx.py` 并由 `finishing/排版规程.md` 接入，移植后**无需另行携带**；仅当真源脚本改动时需重新快照。

## 五、Windows 附注（移植到 Windows 机器时的平台差异）

包内 Python 脚本的文件读写已全部显式 UTF-8，**代码零改动**；差异只在命令写法与环境配置：

1. **命令名**：文档中所有 `python3` 在 Windows 上用 `python`（或 `py -3`）。Python 需 3.10+（engine 代码用 `X | None` 语法）。
2. **控制台编码**：`gates/precheck.py` 输出中文表格，旧版 cmd（cp936）可能对个别符号报编码错。建议用 Windows Terminal，或先设 `set PYTHONUTF8=1`（PowerShell：`$env:PYTHONUTF8=1`）。
3. **skill 安装**：`~/.claude/skills/` 对应 `%USERPROFILE%\.claude\skills\`。复制与路径替换的 PowerShell 版：
   ```powershell
   $DW = "C:\proj\direction_workflow"   # 改成实际放置路径（建议放浅目录防长路径超限）
   Copy-Item -Recurse "$DW\skills\policy-report-assembler","$DW\skills\topic-ideation","$DW\skills\strategy-preread" "$env:USERPROFILE\.claude\skills\"
   $f = "$env:USERPROFILE\.claude\skills\policy-report-assembler\SKILL.md"
   (Get-Content $f -Raw -Encoding utf8) -replace '`blueprints/', "``$DW/blueprints/" -replace '`templates/', "``$DW/templates/" -replace '`skills/', "``$DW/skills/" | Set-Content $f -Encoding utf8
   ```
   （路径分隔符用正斜杠 `/` 即可，Python 与 agent 读取均兼容。）
4. **git 配置三项**（clone 前设，防中文路径与换行问题）：
   ```
   git config --global core.longpaths true      # runs/ 产物中文长路径防 260 字符超限
   git config --global core.autocrlf false      # 防 md 被改写为 CRLF、precheck 读数漂移
   git config --global core.quotepath false     # 终端正常显示中文文件名
   ```
5. **`.env` 位置不变**：仍是包目录的上一级（如包在 `C:\proj\direction_workflow`，则 `.env` 放 `C:\proj\.env`）；`DEEPSEEK_ENV_PATH` 可覆盖。
6. **docx 字体**：`tools/neican_docx.py` 生成 docx 不需要本机字体（只写字体名）；**打开渲染**需仿宋_GB2312、楷体_GB2312、黑体——中文政务机通常已装，缺失时 Word 会自动替换字体、版式略变，可另行安装这两款 GB2312 字体。
7. **文件名合法性**：包内文件名已核无 Windows 非法字符（`<>:"|?*`），全角括号（）合法，可直接 clone。
