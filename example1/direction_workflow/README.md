# direction_workflow — 装配式政策报告工作流

> 总装完成：2026-07-13；主线架构 v2 迭代：2026-07-15。分支 `fix/dna-governance`。领班制施工。
> 一句话：把"写一篇政策报告"拆成**装配工现场造流水线**——不是一个大模型硬写，而是按三张图纸（元框架 v1 槽位层＋v2《问题主线图纸》/元模块契约/调度宪法），从裸主题现场装配「侦察→定向(问题判型)→检索→立论→勾选→观点逻辑确认→组稿→四闸+主线保真→预读→清稿→瘦身聚拢→排版」的本篇专属流水线（全流程 14 步），人只在**两个触点**出场（触点一点方向含判型点选、触点二勾观点），机器守**四道闸＋主线保真检查**兜下限，全程留档可复盘。

## 三、怎么接单（给下一个使用者）

1. **触发装配工**：对装配工 skill 说「接单：<你的主题>」或「装配一篇报告」。它会读三张图纸、建 `runs/<日期-主题缩写>/`。
2. **触点一（你出场·约 1 分钟，含判型点选约 30 秒）**：它跑侦察给你一页态势速览（附候选判型证据）。你**先点「问题判型」**——机器预判的 2–3 个候选切法（六型之一＋一句话主线预览），点选项 ≤4、含逃生口，一刀定全篇骨架；**再签方向书四栏**（议题/倾向箭头/读者层级/禁区，另有半成形直觉选填）。**「用途类型」不再单答，由判型自动派生读者标签。逃生口被你填 = 侦察或判型打偏，它会重跑。**
3. 机器据方向书**按判型主线实例化结构单**（判型轴＋铁三角覆盖轴两栏并记）、真联网全量检索（按主线段加权）、立论出观点清单（约 10 行可错判断句·带主线地址·按主线段分组）。
4. **触点二（你出场·约 30 秒）**：按主线段分组逐行勾/叉/改观点清单。**勾选率 < 50% → 回触点一修方向书，不硬写。**
5. **观点逻辑确认（机器自动跑，你不出手）**：机器把已勾观点归并/定序/写段间承接/建议对归因映射，产《论证结构单》——**默认自动 pass，缺段才回炉插补立论一次**，不构成新增触点。
6. 机器组稿（标题序＝主线序·节间承接·一因一策）→ 跑**四闸＋主线保真检查**（不过按具体违例返修，2 轮不过带病叫你）→ 出预读提词单（永军/曹的考题，供你报送前自备）。
7. 交付工序（agent 非 DeepSeek）：清稿 → 瘦身聚拢（两级 agent）→ 排版导出 `初稿_可交付.docx`（内参版式，`tools/neican_docx.py`）。
8. **触点三（你出场）**：收货五样（可交付 docx 主件＋可阅读＋论证结构单＋底稿＋附件＋需作者定夺清单），写使用体验、回填台账（判型自动、勾选率自动、采用句数事后填）。

**铁律（你和机器共守）**：判据只取自图纸，禁止任何评分/档位/分数；不注入文风规则；每步实体提示词必引图纸原文；零编造全溯源、禁区剪枝不剪反证；两触点必停（触点一含判型点选、触点二认观点；观点逻辑确认默认自动 pass 不新增触点）、四闸必跑（含并列的主线保真检查，四道既有闸原样必跑、称谓道数不改）。
