# 体例蓝图蒸馏法（第 1–2 步）

目标：从范文抽出**主题无关的结构骨架**，并把它直接组织成"检索 / 构思 / 写作 / 审查"四个阶段各自的填充料，写成一份可被用户确认/修改的蓝图。**先读出来，不要套旧体例硬凑；只留结构，抽掉主题。**

体例 = 类型/结构（主题无关）。主题永远走运行时占位符 `【主题】【目标国家】【战略领域】【中国应对主题】`，不进体例。所以蒸馏时把范文里具体国家/数据/事实当"填充示例"，读的是它们背后的**组织方式**。

## 输入范文的选择

- 最好喂**同结构、不同主题**的几篇范文：结构相同能取共识，主题各异能帮蒸馏器把"结构"和"主题"分离干净，体例更纯、更通用。
- 若几篇主题也雷同，体例易夹带主题痕迹、做窄——此时在蓝图里提醒用户。

## 抽什么（按四阶段组织——这就是引擎的主轴）

先定两个总纲，再逐阶段抽：

- **文体定位**：哪一类（经验借鉴 / 战略应对 / 趋势研判 / 多维综述 / 其它）？在"描述 vs 判断"光谱偏哪边？最易被误写成什么（防滑点）？
- **推理链（灵魂）**：从"材料事实"到"中国结论"经过哪几跳，用箭头串出。必须从范文实际论证路径读出，例：外部做法→成因→有效性→迁移前提→中国适配。

然后把结构拆进四阶段：

1. **检索阶段**：要支撑这条推理链，需要哪几类原始材料？给每类一个 ascii key + 一句话职责（即将来的 `retrieval_types`，一般 5–6 类，固定含一类"中国现状/短板"和一类"中国对策依据"）。
2. **构思阶段**：归类方式（是否把多国/多案例归并成 2–3 种模式/类型，还是别的组织法）；判断怎么从材料锻造（推理链每跳如何成立）；建议/对策如何从前文推导。
3. **写作阶段**：正文分几段、每段干什么、段间如何递进；建议条数与每条固定要素（如：回扣前文 + 中国短板 + 迁移前提/抓手 + 责任主体）、加粗领起句等格式。
4. **审查阶段**：本体例的红线（如：按类型归类而非逐国罗列、区分证据状态、强制对策收尾、敏感措辞软化等）——这些就是审查/修改时要核的点。

附：**证据纪律**（是否强求有效性评估证据，还是可多陈述政策文件但须标证据状态）与**体例特有文风**（大多数交全局 policy_style_dna，这里只记体例特有项）随阶段标注。

## 多篇范文怎么处理

- 取**共识结构**：几篇都有的推理链/分段作为主干。
- 差异处在蓝图里标注"范文 A 有 X 段、范文 B 没有"，并问用户取舍。
- 若其中有"反例"（结构不及格，如只判趋势无对策），可单独标为反例，供后续审查识别不及格形态（参照 trend_review 的 sample_manifest 做法）。

## 蓝图模板（第 2 步输出给用户的内容）

```
# 体例蓝图：<拟定中文 label>（slug: <ascii-slug>）

## 总纲
- 文体定位：是什么 / 不是什么 / 防滑点……
- 推理链（灵魂）：<A → B → C → D → 中国结论>

## 检索阶段 → retrieval_types（输出文件名）
- <key1>：职责……
- <key2>：……
- …（5–6 类，含 china_status_and_gaps 类与 response/adaptation 类）

## 构思阶段
- 归类方式：把多国/多案例归并成哪 2–3 种模式/类型，或别的组织法
- 判断锻造：推理链每跳如何从材料成立
- 建议推导路径：<沿推理链逐条推出对策>

## 写作阶段 → 分段结构
- 开篇：给什么判断
- 一、……（干什么、怎么归类）
- 二、……
- 三、中国现状/定位/短板
- 四、中国建议/对策（强制收尾）
- 建议写法：条数…；每条要素…

## 审查阶段 → 体例红线
- 必须核查：…（如按类型归类而非罗列、区分证据状态、强制对策收尾、敏感措辞软化）

## 证据纪律 / 体例特有文风
- ……

## 取自哪几篇范文 + 差异/反例标注
- ……

## 待你确认：推理链、检索类型、构思归类、分段、审查红线、体例名是否照此落盘？需改哪里？
```

## Checkpoint 纪律

- 必须把蓝图发给用户、等确认或修改，**不得跳过直接生成体例目录**。
- 用户改推理链/检索类型/分段/名字后，更新蓝图再进入落盘步。
- 若范文不足以读出某一环（如推理链某跳缺证据），如实写"范文未体现，建议默认 X / 请你定"，不要硬编。
