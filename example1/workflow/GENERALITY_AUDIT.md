# 国际比较报告工作流 · 普适性审计裁决

> 日期：2026-06-25。方法：30-agent 工作流（7 组件写死/参数化扫描 + 6 差异主题覆盖测试 + 16 项对抗复核 + 综合裁决）。
> 目标问题：这个工作流能否普适接下 8 成其他主题的国际比较报告？

## 1. 总裁决：现状约 2 成，且为"伪普适"

- **覆盖测试 6 战 6 败全 poor**：中考改革／校服治理／体育教师培养／校园餐／工程教育／学龄人口调配，逐一对照人类范文，fit 全 poor。失败模式一致：范文是"多维度并列/趋势全景/业务环节铺开"的扁平结构，流水线强套"治理(顶层设计+实施机制)→目的层→中国对策"三章漏斗，丢 5–10 个核心维度。
- **对抗复核 19 项中 17 项确认真写死**。唯一的"参数化承诺" `create_task_state(tasks=...)` 是**死代码**：`run()` 用写死 `_run_task` 序列旁路任务表，注入自定义 tasks 在 `report_pipeline.py:823` 抛 KeyError。
- 真正派生的只有：topic 占位符、第二章维度名（材料聚类）、国别（知识库派生）——只保证"不崩溃"，不保证"合身"。
- **结论：能跑 ≈8 成不报错，但只有 ≈2 成产出结构合身的报告。** 能接住的恰是与 AI+教育同构的主题（强治理 + 清晰目的层）。

## 2. 根因

`通用写作模板v2.md` 自称"主题/国别/维度均不预设"，但 `report_pipeline.py` 把 AI+教育三章章法在四层焊死。**章节蓝图（章数/每章子节/每节走检索还是构思/标题来源/章间依赖）从未抽象成数据，而是以"方法名 + 调用顺序 + 提示词正文"三种形态散落焊死。**

| # | 缺陷 | 位置 | 性质 |
|---|---|---|---|
| R1 | `run()` 22 步任务链逐行硬编码，无蓝图驱动循环 | `report_pipeline.py:78-109` | 最致命 |
| R2 | 第一章焊死"顶层设计+实施机制+1主题特性"，写死在四层 | `report_pipeline.py:82-89`/`task_state.py:56-62`/`3a`正文/`prompt_builder.py:287-293` | 最不可迁移 |
| R3 | 第二章焊死"手段/目的"二分+单一目的层，写死三处 | `第二部分定题.md:7-19`/`prompt_builder.py:296-302`/`report_pipeline.py:750-763` | 次致命 |
| R4 | 原始提示词裸写主题词，占位符够不着（3a"AI+教育"、3c整段教育伦理范例+"完全沿用句式"、第二章人设"教育与科技政策研究员"） | `3a:14,16`/`3c:9-20`/`第二章凝练维度写作模版.md:1` | 确定性污染 |

## 3. 按主题分型（接不住的 8 成）

判别线：主题是否同构于"强治理属性 + 独立目的层 + 国外有成熟经验 + 需向中国转化"，四者缺一即塌。

1. **业务环节铺开型**（校服/校园餐）→ 塌于治理双章（6 并列环节 vs 3 纵向槽）。
2. **扁平多维制度型**（中考改革 10 维）→ 塌于维度数 2 vs 10；伦理治理格无对应硬凑。
3. **趋势综述型**（工程教育）→ 塌于文体（强制 ch3 把综述改成建言书）。
4. **资源调配型**（学龄人口）→ 塌于缺数据预警槽位；本无对策章却被凭空补。

## 4. 改造清单（达 8 成最小集）

设计原则：把章节蓝图从代码/提示词外提为数据；AI+教育保留为默认蓝图保零回归。

**P0 地基（不做则其余无意义）**
- **C1 章节蓝图数据化**：`report_pipeline.py:78-109` 定义 `ReportSpec.chapters[ChapterSpec{id,heading,steps[]}]`，`run()` 改 `for ch in spec.chapters: for step in ch.steps: ...`；现 22 步抽成默认 spec。
- **C2 执行链由任务表驱动 + 接通 tasks 注入**：`DEFAULT_TASKS` 由 spec 派生；建 `task_id→handler` 注册表；`runner.py` 加 `--genre/--report-spec`。修死代码 + 双份真相。
- **C3 去硬编码标题/拼接**：`report_pipeline.py:270-279,367-376` 删字面量标题，按 `ChapterSpec.heading` 或派生；`_assemble_final` 遍历 `spec.chapters`。

**P1 解结构假设**
- **C4 第一章子节可配**：`prompt_builder.py:287-293` 读 `first_subtheme` + **同改 `3a` 模板正文**（只改 Python 是改一半）。
- **C5 第二章二分法给退出口**：`第二部分定题.md` 加"无清晰二分则改 2-3 平行专题"分支；`_extract_chapter2_title` 容忍多主题。

**P2 清污 + 审查解耦**
- **C6 清洗提示词裸主题词**：3a/3c/第二章人设 → 占位符（性价比最高，可与 P0 并行）。
- **C7 审查标准按功能而非章序**：fulltext_review/rewrite/content_structure_review 的"三章递进""每条建议挂国际经验"→功能化 + 退化路径。

估算：**P0+P1 → 5~6 成；+ P2 + 2~3 个新体例各一份 ReportSpec → 8 成。**

## 5. 与 strategic 配刀改造的关系：普适性是地基，先于配刀

- `distill-reasoning-dna` 预设"体例"抽象层，而现在没有——只有 AI+教育一种隐式体例焊死在 `run()`。**C1 的 ReportSpec 就是体例层，也是 EXECUTION_PLAN 里 module.yaml 的配置态，两者合并为一次改造。**
- 可合并：C2 的 handler 注册表预留 `step.cuts` 字段（刀随蓝图注入）；C7 审查功能化与语域闸同层（审查模板正是刀的载体）。
- 必须先做不可合并：C1/C3/C5/C6 是"换主题不走样"的前提，与判断深度无关。结构错了，刀越深越把错误结构雕得越精致——先长对骨架，再用刀长出判断。
- **排序**：C1→C2→C3 → C4→C7 → 体例层之上配刀 + 语域闸。
