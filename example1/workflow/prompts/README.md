# 工程化提示词分块说明

## 1. 核心判断

当前工作流不需要让模型直接输出 JSON。

更合适的方式是：

1. 检索模块：原始检索提示词 + 输入主题 + NotebookLM 知识库边界。
2. 构思模块：原始构思提示词 + 输入主题或上游材料。
3. 写作模块：原始写作提示词 + 检索材料或构思产物 + “只输出正文”的约束。

脚本只负责拼装提示词、传输文件、保存结果。结构化处理放到后处理阶段，不放进当前提示词主流程。

## 2. 通用拼装结构

```text
【本次输入】
报告主题：{{topic}}
知识库名称：{{notebook_name}}
Notebook ID：{{notebook_id}}
{{optional_context}}

【原始提示词】
{{original_prompt_with_topic_replaced}}

【工程化输出要求】
{{minimal_output_contract}}
```

## 3. 原始提示词边界

- `多政策的国际比较报告` 下的原始提示词只读。
- 脚本可以复制原始提示词并替换占位符。
- 脚本不能直接修改原始提示词。
- 如需修改原始提示词，必须先征得用户同意。

## 4. 执行者边界

- NotebookLM skill 只负责检索材料。
- DeepSeek v4 Pro 负责构思和写作。
- Codex 负责编排、传输文件、保存产物。
- DeepSeek 的思考过程不保存、不展示，只保存最终回答。
