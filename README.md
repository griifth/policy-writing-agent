# direction_workflow — 装配式政策报告工作流

> 一句话：把"写一篇政策报告"拆成**装配工现场造流水线**——不是一个大模型硬写，而是按三张图纸（元框架 v1 槽位层＋v2《问题主线图纸》／元模块契约／调度宪法），从裸主题现场装配「侦察→定向(问题判型)→检索→立论→勾选→观点逻辑确认→组稿→四闸+主线保真→预读→清稿→瘦身聚拢→排版」的本篇专属流水线（全流程 14 步）。人只在**两个触点**出场（触点一点方向含判型点选、触点二勾观点，合计约 90 秒），机器守**四道闸＋主线保真检查**兜下限，全程留档可复盘。

- **给撰写者/操作员**：直接看 [USAGE.md](USAGE.md)（14 步全流程一图＋两触点 90 秒操作法＋交付物用法）。
- **要把包搬到新机**：看 [移植说明.md](移植说明.md)＋[依赖说明.md](依赖说明.md)。

## 快速开始

```bash
# 1. 安装 Python 依赖（排版工序需要）
pip install -r requirements.txt

# 2.（可选，生产单才需要）在本包的上一级目录放 .env，写入 DEEPSEEK_API_KEY
#    试跑单可由 agent 直写，无需密钥。详见 依赖说明.md

# 3. 在装有本包 skills 的 Claude Code / agent 会话中，对装配工说：
#    「派单：<你的主题>」——派单员（order-dispatch）会问清决策模式等五个变量，
#    生成本单《接单提示词》（任务简报）落 orders/ 并派发执行 agent；
#    手里有现成资料就顺手一并给，机器自动编目为 U 类锚并默认高优先使用
```

需要联网（侦察与检索是真网搜）。skill 既可装进 `~/.claude/skills/` 按名触发，也可由 agent 直接按包内路径读取执行（见 移植说明.md）。

## 架构一图

```
        ┌──────────── 三张图纸（blueprints/ 快照）────────────┐
        │  元框架 v1（槽位族谱）＋元框架 v2《问题主线图纸》     │
        │  → 元模块契约.md → 调度宪法.md（八条+形制）           │
        └───────────────────────┬────────────────────────────┘
                                │ 每接一单先读
                                ▼
   裸主题 ──► [装配工 skill] policy-report-assembler（现场造各模块「实体提示词」，每个必引图纸原文）
                 │
                 ├─①侦察 ──真联网──► 态势速览一页（四栏＋候选判型证据＋逃生口）
                 │            【触点一·人点选】► 方向书：点「问题判型」（六型一刀定骨架）＋签四栏
                 ├─结构单实例化（判型主线驱动：判型轴＋铁三角覆盖轴两栏并记）
                 ├─②全量检索 ──真联网──► 料包（按主线段加权、禁区剪枝但反证不剪）
                 ├─③立论（注入 topic-ideation·定题立论顾问）──► 观点清单（可错判断句×N·带主线地址）
                 │            【触点二·人勾/叉/改】► 已勾清单（勾选率<50%回触点一）
                 ├─②.5 观点逻辑确认 ──► 论证结构单（归并/定序/承接/一因一策；默认自动 pass）
                 ├─④组稿（注入 strategy-preread·结构预读顾问）──► 成稿（标题序=主线序＋边角料箱）
                 ├─⑤机械闸族 [gates/]：precheck.py 语域预检＋三道 LLM 闸＋主线保真检查 5 项
                 │            └─ 只出「违例清单」，零分数零档位；返修 2 轮不过带病叫人
                 └─⑥预读提词（真调两个顾问 skill，只出考题不打分）
                                │
              交付工序：清稿 → 瘦身聚拢（两级 agent）→ 排版 docx（内参版式）
                                │
                 【触点三·撰写者收货】► 使用体验＋自估采用句数 ► 台账行
```

**铁律**：判据只取自图纸，禁止任何评分/档位/分数；不注入文风规则；每步实体提示词必引图纸原文；零编造全溯源、禁区剪枝不剪反证；两触点必停、四闸必跑（含并列的主线保真检查）。

## 系统边界（不做什么）

- **不打分、不评档、不判稿件优劣**——判定权在人；机器只出违例清单与考题。
- **不替你立场**——观点清单是候选，勾选权在撰写者；夹带私货会被方向保真闸打回。
- **不保证事实无误**——保证可溯源（每个事实带来源锚），报送级核验仍需人工抽查。
- **不代报送**——终点是交付给撰写者。

详见 [USAGE.md](USAGE.md) 第五节边界声明。

## 维护纪律

1. 三张图纸的设计真源在内部仓库 `records/`，包内 `blueprints/` 是快照——改设计先改真源、再重新快照（快照头注注明日期）。
2. skill 双份：`~/.claude/skills/` 安装件与包内 `skills/` 母本互为副本，内核改动两处同步。
3. 词表（`gates/register_blacklist.md`、`gates/lexicon_blacklist.md`）与纲要地图（`skills/strategy-preread/references/纲要地图.md`）随政策周期滚动更新，来源日期必须标注。
4. 两个顾问思维模型（topic-ideation、strategy-preread）为"论文＋会议"蒸馏 V2，蒸馏溯源材料存内部仓库、不随包分发；重蒸后接口不变。
5. 设计史、施工报告、历史 runs 与 skill 版本快照均存内部仓库分支，不随发布包。
