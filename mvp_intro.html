NotebookLM-backed MVP

Policy Writing Agent

一个把政策知识库转化为热点研判报告的可执行写作流水线：先拆问题，再检索材料，再组织材料包，最后按章节契约生成报告并通过审查门禁。

ReportTask主题、notebook_id、章节、模式
QueryJobs六类 NotebookLM 检索任务
MaterialPack热点、主题、工具、影响、判断
SectionDrafts五个章节契约化写作
ReviewGates结构化 verdict 和终稿装配
功能 架构 流程 如何使用 产物 下一步

这个 MVP 解决什么

MVP 的目标不是替代 NotebookLM，也不是建设新的来源追溯系统。NotebookLM 负责知识库、来源和问答；本 Agent 负责把写作任务工程化，保证报告从材料到判断再到章节都有中间产物和审查记录。

功能一

拆问题

把“写一份热点研判报告”拆成全库扫描、主题归类、热点深挖、比较分析、影响研判和启发提炼六类 QueryJob。

功能二

定维度

使用 dimension_registry.yaml 固定热点、主题、比较、影响、启发五类字段，减少模型自由发挥。

功能三

组织材料包

将 NotebookLM 回答整理成 MaterialPackage，包含热点、主题、政策工具、影响、风险和可写判断。

功能四

控制报告结构

通过 POLICY_REPORT_PLAN.md 和 section_contracts.yaml 控制每章职责，避免章节互相抢内容。

功能五

材料转文章

章节写作只消费材料包和判断-材料矩阵，缺材料时保留 MATERIAL_NEEDED，不编造判断。

功能六

审查门禁

生成 Plan、Retrieval、Material、ClaimScope、KillArgument 等审查报告，所有结果用统一 verdict 记录。

架构

系统采用模块化流水线。NotebookLM 只通过 Adapter 使用；业务模块不直接拼命令，也不依赖 NotebookLM 当前 notebook 状态。

ReportTask ↓ QueryPlanner ↓ NotebookLMAdapter ↓ MaterialPackBuilder ↓ MatrixBuilder ↓ SectionPlanner ↓ SectionComposer ↓ ReviewGates ↓ ReportAssembler ↓ ManifestWriter

关键边界

  • NotebookLMAdapter 是唯一能调用 NotebookLM CLI 的模块。
  • MaterialPackage 是写作中间件，不承担来源追溯职责。
  • PolicyClaim-Material Matrix 控制判断能出现在哪些章节。
  • ReviewGates 只输出审查结果，不直接修改正文。
  • MANIFEST.md 记录每个产物的路径和生产者。
模块 输入 输出 职责边界
QueryPlanner ReportTask、维度 schema、章节契约 query_jobs.json 只生成检索任务，不解释材料。
NotebookLMAdapter QueryJob query_results/*.json 封装 real/mock 两种模式。
MaterialPackBuilder QueryResult material_packages/*.json 整理材料，不写正文。
MatrixBuilder MaterialPackage 比较矩阵、影响表、判断-材料矩阵 把材料转成可消费结构。
SectionComposer 章节契约、材料包、矩阵 section_drafts/*.md 只按材料生成章节草稿。
ReviewGates 计划、材料、章节、终稿 review_reports/*.json 只审查，不直接改稿。

运行流程

一次运行会生成独立的 runs/<run_id>/ 目录。每一步都有落盘产物，因此可以复核、重跑或接入后续自动化。

1任务配置读取 report_task.yaml，确定主题、notebook_id、章节和模式。
2检索规划生成六类 QueryJob，覆盖热点、主题、深挖、比较、影响、启发。
3材料加工调用 Adapter 得到 QueryResult，再合并成 MaterialPackage。
4章节写作根据报告计划和章节契约生成五个 Markdown 草稿。
5审查装配执行 review gates，生成 final_report.md 和 MANIFEST.md。

如何使用

当前默认使用 mock mode，因此不需要 NotebookLM 登录，也能完整验证流程和产物结构。

1. 运行 mock workflow

cd /Users/hujingkai/Documents/New\ project/policy-writing-agent
python3 src/runner.py --task config/report_task.yaml --run-id demo

运行后查看 runs/demo/final_report.md 和 runs/demo/MANIFEST.md。

2. 接入真实 NotebookLM

# 编辑 config/report_task.yaml
task:
  notebook_id: "你的 NotebookLM ID"

execution:
  mode: "real"

real mode 会通过 NotebookLMAdapter 调用 NotebookLM CLI。NotebookLM 不可用时会输出结构化错误，不静默跳过。

当前 MVP 已通过 mock 验证：六类 QueryJob、五个章节草稿、六个 review report、终稿附录和 MANIFEST 都能生成。

Verdict 含义 处理方式
PASS检查通过。继续下一步。
WARN可继续，但需要谨慎表达。降低判断强度。
BLOCKED缺前置材料或字段。生成 follow-up QueryJob。
FAIL计划或产物不合格。返回上游重做。
ERROR工具或格式错误。修复执行环境或输入。
NOT_APPLICABLE检查过，确实不适用。记录后跳过。
